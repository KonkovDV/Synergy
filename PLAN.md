# PLAN.md — план работ v5 → финал (для команды и ИИ-ассистента)

> **Протокол сессии ИИ.** Начало: прочитать `MEMORY.md`, затем этот файл, затем только файлы задачи (карта — `docs/ARCHITECTURE.md`; не сканировать весь проект). Одна сессия = один пункт плана (или 2–3 мелких). Конец: `npm test` → `npm run build` → для UI `node tests/e2e/v5.mjs` → обновить `MEMORY.md` (журнал, решения, открытые вопросы) и отметить пункт здесь → коммит. Принципы обязательны: DRY, KISS, SOLID, единый язык (`docs/GLOSSARY.md`). Если контекст стал большим или ответы теряют качество — остановиться, обновить `MEMORY.md`/`PLAN.md`, продолжить в новой сессии.
>
> **Бюджет ИИ.** Главный расход — повторное чтение контекста. Не читать файлы целиком без нужды, не выводить большие логи, правки — пакетами. Оценка в скобках у пунктов: S ≈ 5 % лимита сессии, M ≈ 15 %, L ≈ 30 %.

- [ ] **2.1 P0 (M)** Плейтест 5+ человек (в идеале — пользователи протезов на сессиях с экспертами): онбординг → «Первые шаги» → план дня → проверка навыка. Фиксировать: где застряли, ошибки понимания, SUS (10 вопросов), время до первой звезды. Итоги — в `MEMORY.md`.

- [ ] **2.3 P1 (M) Ко-адаптивная калибровка** (Hahne 2015 — человек и алгоритм учатся вместе; инкрементальное обучение, UNB 2025): `core/calibration.js` → `AdaptiveCalibration`: медленное обновление покоя (только во время подтверждённого покоя) и комфортного максимума (перцентиль пиков) с коэффициентом забывания и границами ±20 %; при дрейфе > 30 % — подсказка «Пора перекалибровать» (электроды сместились, кожа, усталость). Выключено в проверке навыка. Тест: синтетический дрейф → калибровка сходится, скачок → предупреждение.
- [ ] **2.4 P1 (M) Затухающая обратная связь по навыку** (guidance hypothesis, Winstein & Schmidt 1990; отсроченная обратная связь улучшает удержание — Stuttaford 2023, Dupan 2025): шкала силы и полоски A/B показываются тем реже, чем выше навык (100 % → 50 % → итог после попытки), вместо «всё или ничего». `games/base.js` (`feedbackLevel`), `config.js`. Тест: уровень навыка → доля скрытых кадров.
- [ ] **2.5 P1 (S) Чередование в плане дня** (контекстная интерференция: перемешанная практика лучше удерживается, чем блочная): `buildDailyPlan` — разные игры подряд, слабейший навык дважды за неделю, интервальное повторение. Тест в `v5.test.mjs`.
- [ ] **2.6 P1 (M) Пропускная способность по закону Фиттса** в «Проверке навыка» (стандартная метрика миоуправления; Scheme & Englehart; ISO 9241-411): 1D-задачи «достигни уровня» с разными D и W, ID = log2(D/W + 1), TP = ID / MT (бит/с), перелёты и эффективность пути. `games/assess.js`, отчёт, таблица в «Прогрессе». Тест: автопилот даёт конечный TP > 0, пассивный — нет попыток.
- [ ] **2.7 P1 (M) Реалистичный классификатор в эмуляторе:** путаницы жестов не равновероятные, а по матрице из открытых данных (EMG-EPN-612/NinaPro: близкие жесты путаются чаще — щепоть↔ключ, указательный↔класс), зависят от силы и усталости. `input/emulator.js` + таблица в `config.js`. ## Правила для ИИ при изменениях

1. Сначала тест или его правка, затем код; `npm test` перед каждым коммитом.
2. Новые параметры — в `src/config.js`; новые термины — в `vocabulary.js` и `docs/GLOSSARY.md`.
3. Формат внешних данных — только в `parseExternal()`.
4. Новая игра — по инструкции `docs/ARCHITECTURE.md` («Как добавить игру»); тесты появятся автоматически.
5. Никаких медицинских обещаний; метрики — «игровые»; ссылки на исследования — только проверенные.
6. Новый сценарий — строка в `docs/SCENARIOS.md` с проверкой.
7. Android: новые API — сначала заглушка, затем `VERIFY_API=1`.
8. Без открытой лицензии и чужих ассетов (п. 5.5, 6.6 Правил).
9. После каждой сессии — запись в `MEMORY.md` («Журнал»).
