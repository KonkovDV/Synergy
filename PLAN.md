## A. Протокол каждой сессии ИИ

1. **Старт (≤ 5 % бюджета).** Прочитать `MEMORY.md` → этот файл (разделы B и C) → только файлы текущей задачи. Карта слоёв — `docs/ARCHITECTURE.md`. Весь проект **не сканировать**: искать `grep -rn`, читать фрагменты `sed -n 'a,bp'`.
2. **Базовая линия до любых правок** — в корне репозитория:
   ```bash
   npm ci && npm test                       # ожидается: # tests 72, # fail 0
   node tools/check-submission.mjs --draft  # ожидается: 0 ошибок, 2 предупреждения (AUTHORS, дата первого коммита)
   ```
   Если базовая линия не совпала — сначала понять почему, записать в `MEMORY.md`, затем работать.
3. **Одна сессия = один пункт раздела B** (или 2–3 пункта размера S). Порядок — как в B.
4. **Цикл изменения:** тест (или правка теста) → код → `npm test` → для UI ещё `node tests/e2e/v5.mjs` → документы (`SCENARIOS`, `GLOSSARY`, `GAME_DESIGN`/`ARCHITECTURE` при необходимости) → коммит.
5. **Финиш (≤ 10 %):** раздел B.9. Без `npm run pack` сессия не закончена.
6. **Стоп-правило.** Если контекст стал большим (ответы теряют точность, приходится перечитывать уже прочитанное) или две попытки подряд не прошли тесты — остановиться, записать в `MEMORY.md` «что сделано, что сломано, следующий шаг», отметить пункт здесь и продолжить в новой сессии.
7. **Обязательные принципы:** DRY (параметры — `src/config.js`; словарь — `src/core/vocabulary.js`; формат кадров — `parseExternal()`; шаг цепочки — `GameRunner`), KISS (ванильный JS, без фреймворков и новых зависимостей в продукте), SOLID (новая игра = файл + строка в `registry.js`; новый источник = `sample(now)` или `BridgeSource.feed`), единый язык (`docs/GLOSSARY.md`).

### B.3 Ко-адаптивная калибровка (M) — PLAN 2.3

**Зачем:** с реальными датчиками покой «плывёт» (пот, сдвиг электродов, усталость). Опора: Hahne 2015 (человек и алгоритм подстраиваются вместе), UNB 2025 (инкрементальное обучение).

Дизайн (KISS: подстраивается только **покой**; для усиления — только предупреждение):
- `src/config.js`: `CALIBRATION_ADAPT = { tauS: 60, quietMs: 1000, quietFactor: 0.5, maxShift: 0.2, driftWarn: 0.3 }`.
- `src/core/calibration.js`: чистый класс `RestTracker`. `update(raw, intent, dt)` работает только при `intent.command === REST`, когда оба нормализованных канала ниже `quietFactor × onThreshold` дольше `quietMs`: `rest[ch] += (raw[ch] − rest[ch]) × dt / tauS`; сдвиг ограничен `±maxShift × (max − rest₀)`. `drift()` возвращает долю смещения; при `> driftWarn` — флаг «пора перекалибровать».
- `src/core/signal.js`: `SignalPipeline` получает необязательный `restTracker` и нормализует по его текущему покою. Включать **только** для источника `bridge`: **не** для экранного эмулятора и **не** в «Проверке навыка» (там `Game.adaptive === false`, нужна сравнимость).
- `src/app.js`: `createPipeline()` подключает трекер. `finishSession()` сохраняет подстроенный покой в `calibrations.bridge` (с `adaptedAt`), если сдвиг в границах; иначе — тост «Пора перекалибровать».
- UI: в итогах — строка «Калибровка подстроилась под датчик» или предупреждение; в «Настройках» — переключатель «Подстраивать покой» (по умолчанию включён).

Тесты (`tests/calibration.test.mjs`):
1. Покой медленно растёт 0 → 0,1 за 60 с → нормализованный покой остаётся ниже `onThreshold`, ложных команд нет.
2. Длительное сжатие не сдвигает покой (адаптация только в подтверждённом покое).
3. Скачок покоя на 40 % → сдвиг ограничен `maxShift`, `drift() > driftWarn`.
4. В «Проверке навыка» трекер не создаётся.

Документы: `SCENARIOS.md` 4.6, `INTEGRATION.md` (калибровка), `GLOSSARY.md` («Подстройка покоя»).

### B.4 Закон Фиттса в «Проверке навыка» (M) — PLAN 2.6

**Зачем:** пропускная способность в бит/с — стандартная метрика пропорционального миоуправления (Scheme & Englehart; ISO 9241-411). Жюри-академики её узнают.

Дизайн (только пропорциональная схема; пороговая и жесты не меняются):
- Блок из 6 попыток «достигни уровня»: расстояние D ∈ {0,3; 0,55; 0,8} от покоя × ширина W ∈ {0,12; 0,24}; порядок фиксирован (seed проверки).
- `ID = log2(D / W + 1)` (формулировка Шеннона). `MT` — время от показа цели до **входа** в цель, после которого удержание 0,5 с завершилось (само удержание из MT вычитается). `TP = среднее(ID / MT)` по выполненным попыткам («среднее средних» по ISO 9241-411). Дополнительно: перелёты и эффективность пути = D / пройденный путь интенсивности.
- Поля в `details`: `throughputBps`, `fittsTrials`, `pathEfficiency`. Отчёт (HTML/CSV) и таблица «Прогресса» — столбец «ПС, бит/с».
- В питче цифры **не сравнивать** со статьями (другие задачи и устройства); говорить «растёт ли у вас неделя к неделе».

Тесты: бот — `TP ∈ [0,5; 8]`; модель новичка — `TP` ниже бота; бездействие — нет выполненных попыток, `TP = null`; формула ID на известных значениях (D = 0,3, W = 0,12 → ID ≈ 1,807).

## C. Опыт прошлых сессий — грабли и как их обходить

### C.1 Технические

1. **Кириллица в регулярках JS:** `\w` совпадает только с ASCII. Использовать `[а-яёa-z]` (см. `tools/check-submission.mjs`, `const W`). Любой новый фильтр проверять на списке «старых плохих» и «допустимых» фраз.
2. **`pkill -f "шаблон"` убивает собственную оболочку**, если шаблон есть в её командной строке. Сервер запускать отдельным вызовом: `nohup python3 tools/serve.py --dist --port 8091 >/dev/null 2>&1 &`; останавливать по PID или `pkill -f "[s]erve.py"`.
3. **`.gitignore` не убирает уже отслеживаемые файлы.** Из-за этого в 5.1.0 `dist/` был в git, а в архиве его нет, и ворота падали с `ENOENT`. Теперь проверка ловит артефакты сборки в git; архив проверять **только** через `npm run pack` (распакованная копия).
4. **Импорт тестового файла повторно регистрирует его тесты** — общие помощники только в `tests/helpers.mjs`.
5. **Android без SDK:** заглушки в `android/stubs` должны совпадать с платформой побайтно — `VERIFY_API=1` (Robolectric android-all 29, 131 МБ, кэш `tools/.cache`). Новый API: сначала заглушка, потом проверка.
6. **WebView ≠ браузер:** нет Web Speech, blob-загрузок и Web Bluetooth → нативный мост `window.SynergyNative` (`speak/stop/share/print`). Новые возможности закладывать с проверкой `globalThis.SynergyNative?.метод`.
7. **Полностраничные скриншоты Playwright** рисуют липкие панели посреди страницы — это не ошибка вёрстки.
8. **Бот ≠ человек:** автопилот видит задание и не опаздывает. После любой правки баланса запускать модель новичка (`playNovice` в `tests/helpers.mjs`); её допуски закреплены в `tests/human.test.mjs`.
9. **Навыки считаются по исходным допускам уровня,** а очки — по адаптированным; не смешивать, иначе облегчение «раздувает» навык.
10. **Сеть среды:** `WebFetch` блокирует часть доменов (codenrock.com, motorica.org, docs.github.com, rb.ru, tproger.ru) — использовать `WebSearch`; Maven Central и npm доступны.

### C.2 Продуктовые и юридические

1. **Цифры в документах сверяет `check:submission`** (тесты, размер APK, версии). В README/JURY/MEMORY писать только те цифры, которые скрипт умеет проверять, или добавить проверку.
2. **Никаких завышенных научных формулировок:** «игровая метрика, которую исследование связывало с…», а не «предсказывает» или «доказано». Фильтр стоит в воротах.
3. **Открытую лицензию не ставить** (п. 6.6 + ГК РФ ст. 1235 п. 7). **Текст правил в репозиторий не класть** — только цитаты в `docs/TASK.md`.
4. **Даты коммитов не менять никогда.** Вопрос о наработках до 28.10 решается письмом Организатору (0.6).
5. **Ключей подписи в репозитории нет и не будет;** релиз — только своим ключом из секретов.
6. **Пол пользователя неизвестен:** формулировки интерфейса нейтральные («Есть усталость», а не «Устал»).
7. **Безопасность выше мотивации:** боль → отдых без потери серии; новые механики не должны поощрять тренировку через боль или усталость.

### Риски

| Риск | Вероятность | Мера |
|---|---|---|
| Формат эмулятора несовместим | средняя | один парсер, фикстуры, `--stdin`, день 1 фазы 1 |
| Набор жестов ломает игры | средняя | B.2 (один файл + учебная замена) до 28.10 |
| APK не стартует на части устройств | средняя | 0.2 до 05.11; PWA/HTML — запасной путь |
| Критерии не совпали с гипотезой | средняя | 1.1 в день публикации |
| Наработки до 28.10 не засчитают | низкая–средняя | 0.6; честная хронология |
| Нет пользователей протезов для плейтеста | высокая | эксперты Моторики; добровольцы + оговорка в питче |
| Документы разошлись с продуктом | низкая | `check:submission`, `npm run pack` |
| Контекст ИИ переполнен | высокая | протокол A, стоп-правило, одна задача на сессию |
