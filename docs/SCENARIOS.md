# Сценарии работы и граничные случаи

Спецификация поведения v5: что делает программа в каждом сценарии и чем это проверено.
Принцип: **безопасность → понятность → мотивация**. Если правила конфликтуют, побеждает левое.

## 1. Главный поток дня

```
Онбординг (1 раз) → Первые шаги (обучение, можно пропустить)
        ↓
Главная → «Начать» → Самочувствие (1 раз в день) ─┬─ сильная боль → «Сегодня отдых», план закрыт
                                                   ├─ умеренная боль / сильная усталость → лёгкий план (1 упр. + проверка)
                                                   └─ норма → обычный план (3 упр. + без подсказки; ребёнок — 2)
        ↓
Игра (старт удержанием A) → Итоги (удержание A = главное действие) → Отдых 20 с (ребёнок 15 с) → Игра …
        ↓
Итоги последнего пункта → «Насколько тяжело было?» → Главная (план ✓, +60 XP)
```

| # | Сценарий | Ожидаемое поведение | Проверка |
|---|---|---|---|
| 1.1 | Первый запуск | Онбординг: что это, безопасность, схема управления, сторона протеза, кто занимается (взрослый/ребёнок) → предложение пройти «Первые шаги» | e2e smoke |
| 1.2 | «Первые шаги» | Каждый шаг закрывается сам, когда команда удержана; через 8 с без успеха — подсказка; можно пропустить шаг/всё; по окончании — достижение «Первые шаги» | `tutorial` unit |
| 1.3 | Самочувствие: сильная боль | План не стартует, на главной «Сегодня — отдых» и кнопка «Изменить ответ»; свободная игра доступна с предупреждением | `wellbeing` unit, e2e |
| 1.4 | Самочувствие: умеренная боль или сильная усталость | План сокращается: выполненные пункты + 1 упражнение + проверка без подсказки; метка «лёгкая» | `lightenPlan` unit |
| 1.5 | Самочувствие пропущено | Записывается «пропущено», повторно не спрашивается в этот день | — |
| 1.6 | Смена схемы управления в течение дня | План пересобирается под новую схему; если сегодня был ответ «лёгкая», он применяется и к новому плану | `dailyPlan` unit |
| 1.7 | Признаки усталости | ≥ 3 упражнения, ≥ 6 мин и результат упал на ≥ 20 очков от первых двух → на итогах «Пора отдохнуть», главное действие = «Закончить на сегодня», «Всё равно продолжить» — вторичная кнопка | `fatigueSigns` unit |
| 1.8 | Дневной лимит (30 мин, ребёнок 20 мин) | Та же логика, что 1.7; на главной предупреждение | — |
| 1.8a | Интервальное повторение | Игра без занятий 7 дней поднимается в плане на 21 очко приоритета, даже если её навык не самый слабый | `spaced plan` unit |
| 1.9 | План выполнен | Кнопка «План выполнен ✓» неактивна, бонус XP начислен один раз | `completePlanItem` unit |
| 1.10 | Полночь во время тренировки | Упражнение записывается в день завершения; серия и план считаются по нему | `dayKey` |

## 2. Упражнение

| # | Сценарий | Ожидаемое поведение | Проверка |
|---|---|---|---|
| 2.1 | Старт без касания | Удержание A `dwellS` (0,6–2,5 с, по умолчанию 1 с) → отсчёт 3-2-1 → старт; кисть сбрасывается | e2e |
| 2.2 | Адаптивная сложность | После каждой попытки доля успехов за последние 4: > 87 % → допуски −25 % шага, < 63 % → +25 %; предел ±30 % допуска; итог «сложность подстраивалась» | `adaptive` unit, games |
| 2.2a | Затухающие подсказки | Навык игры < 60 — шкала всегда; 60–79 — скрыта в каждой 3-й попытке; ≥ 80 — в каждой 2-й; на заставке — пояснение; результат показывается после попытки; в демо — всегда видна | `guidance` unit |
| 2.3 | Испытание без подсказки | Сложность фиксирована, живая обратная связь скрыта, счёт «—» до конца | games |
| 2.4 | Пропал сигнал (внешний источник) | Через 300 мс: упражнение и таймеры замирают, кисть держит позицию, подсказка «Нет сигнала», голосом — сразу | `watchdog` unit |
| 2.5 | Приложение свёрнуто | Пауза | e2e |
| 2.6 | Пассивный игрок | Ни одной звезды ни в одной игре/уровне/схеме (кольца сбоку недостижимы без усилия даже при максимальном облегчении) | games |
| 2.7 | Темп игры 60–100 % | Игровой мир медленнее, закон управления кистью — в реальном времени; компенсация задержки в «Ритме» пересчитывается; длительность в отчёте — реальная | games |
| 2.8 | Демо | Автопилот ведёт эмулятор тем же путём сигнала; прогресс не меняется | games |

## 3. Проверка навыка (раз в неделю)

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| 3.1 | Протокол | Фиксированный набор и порядок попыток (seed 2026), удержание 1 с, лимит 7 с, покой 0,6 с между попытками, адаптация и подстройка покоя выключены. Пропорциональная схема: 6 попыток «выйти на уровень» — расстояние 30/55/80 % × ширина окна 12/24 %, удержание 0,5 с — и 2 коактивации |
| 3.2 | Метрики | Доля выполненных, время выбора (до первого верного кадра), время выполнения, точность (верная доля активного времени), перелёты (пропорц.). Пропорциональная схема ещё: пропускная способность (ПС, бит/с) = среднее ID/MT по выполненным попыткам, ID = log₂(D/W + 1), MT — до входа в окно без учёта удержания; эффективность пути. Бездействие → попыток нет, ПС «—» |
| 3.3 | Напоминание | Карточка на главной: «пора» через 7 дней после последней проверки в этой схеме |
| 3.4 | Тренд | «Прогресс» → таблица последних проверок; отчёт для специалиста |

## 4. Источники сигнала

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| 4.1 | Экранный эмулятор | Площадки A/B (место касания = сила, без перетаскивания), A+B, 7 кнопок жестов, клавиатура |
| 4.2 | WebSocket | Переподключение 0,5 → 5 с; статус в игре; кадры > 4 КБ отбрасываются |
| 4.3 | Bluetooth (NUS) | Выбор устройства по нажатию; строки из уведомлений собираются из кусков; 3 попытки переподключения; калибровка обязательна (сырые единицы АЦП) |
| 4.4 | Android-оболочка | `pushFrame()` из нативного SDK; голос — нативный TTS |
| 4.5 | Неверные кадры | NaN, отрицательные, неизвестный жест, устаревшее время → игнор |
| 4.6 | Дрейф покоя (внешний источник) | После 1 с подтверждённого покоя уровень покоя медленно (τ = 60 с) следует за сигналом; сдвиг ≤ 20 % диапазона калибровки, растяжение не меняется. В итогах: «Калибровка подстроилась…» (сдвиг сохранён) или «Пора перекалибровать» — дрейф > 30 % либо канал включён > 15 с подряд (скачок: сместился электрод). Не работает для экранного эмулятора, демо и «Проверки навыка»; выключается в Настройках («Подстраивать покой») |

## 5. Данные и приватность

| # | Сценарий | Ожидаемое поведение |
|---|---|---|
| 5.1 | Хранилище недоступно (приватный режим) | Работа в памяти + предупреждение в настройках |
| 5.2 | Повреждённые данные | Копия в `synergy.v4.corrupt`, старт с чистого состояния |
| 5.3 | Резервная копия | Экспорт JSON; импорт: ≤ 5 МБ, проверка схемы, неизвестные/неверные по типу настройки отбрасываются, подтверждение перезаписи |
| 5.4 | Демо-профиль для презентации | Синтетические 3 недели в памяти, баннер «Демо-профиль», реальные данные не трогаются; выход — перезагрузка из хранилища |
| 5.5 | Отчёт для специалиста | JSON, CSV, печатная HTML-страница (экранирование всех строк) |
| 5.6 | Сброс | Подтверждение; в детском режиме — за PIN |

## 6. Доступность

| # | Потребность | Решение |
|---|---|---|
| 6.1 | Одна рука / протез на другой руке | Всё управление — одной рукой; старт и «Дальше» удержанием мышцы; зеркальная кисть для левой стороны |
| 6.2 | Слабое зрение | Крупный текст 115/130 %, высокий контраст, озвучивание подсказок и итогов |
| 6.3 | Слабый слух | Вибро-метроном в «Ритме», визуальная пульсация такта, все звуки дублированы текстом |
| 6.4 | Чувствительность к движению | «Меньше движения»: без частиц, вспышек и анимаций (+ системная настройка) |
| 6.5 | Моторные ограничения, тремор | Темп игры, время удержания для «без касания», адаптивная сложность, гистерезис порогов |
| 6.6 | Ребёнок | Детский режим: короче план, отдых и лимит; PIN родителя на настройки |

## 7. Отказоустойчивость

| # | Сбой | Поведение |
|---|---|---|
| 7.1 | Исключение в кадре игры | Тост «Ошибка кадра», цикл продолжается, игра останавливает отрисовку, данные не теряются |
| 7.2 | Нет WebAudio / вибрации / TTS | Функция молча отключается, игра идёт |
| 7.3 | Нет Web Bluetooth | Кнопка объясняет, где работает (Chrome Android/ПК) и альтернативу (`pushFrame`, мост) |
| 7.4 | Ручная правка localStorage | Схема и типы проверяются при загрузке |
