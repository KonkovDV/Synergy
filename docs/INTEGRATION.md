# Подключение эмулятора организаторов, датчиков или протеза

## Контракт кадра (SignalFrame)

```json
{ "a": 0.42, "b": 0.05, "gesture": "pinch", "confidence": 0.91, "effort": 0.6 }
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `a`, `b` | да (для жестов можно опустить) | огибающая ЭМГ каналов A (сжатие) и B (раскрытие), ≥ 0, лучше ≥ 20 кадров/с. Если не 0..1 — выполните калибровку. **Сырая (двуполярная) ЭМГ** распознаётся по первому отрицательному значению: дальше каждое сообщение входит в RMS-огибающую за 150 мс (`EnvelopeFilter`), в статусе — «сырая ЭМГ → огибающая». Для честной огибающей сырой сигнал нужен с частотой ≥ 500 Гц; лучше присылать готовую огибающую |
| `gesture` | нет | id (`rest, fist, open, pinch, point, key, thumb`), русское имя (`Кулак`, `щепоть`…, регистр не важен), индекс класса 0–6 (`CLASS_ORDER`) или синоним (`close`, `palm`, `tripod`, `lateral`…). Имена обучения жестам UBI4 из Motorica Start (`Neutral`, `Close`, `Open`, `Pinch`, `Indication` и подписи его экрана) понимаются с 5.29. **Класс не из набора** (`Wrist_Flex`, индекс 7…) — покой с уверенностью 0, связь не теряется; под полем — «жест не из набора игры: …» |
| `confidence` | нет | уверенность классификатора 0..1; ниже 0,6 → «покой» |
| `effort` | нет | сила жеста 0..1 (иначе берётся max(a, b)) |

Время кадра проставляется **при получении** — часы источника не важны. Если 300 мс нет кадров — упражнение замирает.

Принимаются и другие формы: `{ch:[a,b]}`, `{channels:[…]}`, `{emg:[…]}`, `[a,b]`, строка `"a b"`/`"a,b"` (пустая строка — не кадр, 5.11), `{class|label: …, prob|p: …}`. Калибровка работает в любых единицах источника (вольты, отсчёты АЦП). Номера каналов для A/B в многоканальном массиве задаются в `parseExternal(msg, {channelA, channelB})`.

**Когда 28.10 опубликуют эмулятор:** изменить только `src/input/bridge.js → parseExternal()` (+ тест в `tests/core.test.mjs`). Если эмулятор — программа с выводом в консоль, используйте `--stdin` без изменения кода игры.

### Снимок Motorica Start (контракт v1, 5.21)

Так Motorica Start передаёт сигнал своей игре Motorica Kart. Контракт открыт в её исходном коде: [HakerFromRussia-XD/1_game_stk](https://github.com/HakerFromRussia-XD/1_game_stk) (`GameControlSnapshot.java`, `IGameControlService.aidl`, `motorica_game_control.cpp`; «Motorica-maintained SuperTuxKart fork for Motorica Start controller integration»). «Синергия» принимает снимок как есть, через любой транспорт выше:

```json
{ "version": 1, "seq": 1842, "timestampMs": 1792540800000, "openLevel": 12, "closeLevel": 168, "connected": true }
```

| Поле | Как читает «Синергия» |
|---|---|
| `closeLevel` | канал A (сжатие): 0…255 → 0…1 |
| `openLevel` | канал B (раскрытие): 0…255 → 0…1 |
| `connected: false` | протез не на связи: последний кадр сбрасывается, через 300 мс — «нет сигнала» и пауза. Уровни 0/0 при этом не считаются покоем |
| `seq` | тот же номер — не новый кадр. Хост, который пересылает последний снимок каждые 33 мс, не продлевает жизнь остановившемуся устройству |
| `version` | только 1: другая версия может означать другие уровни |
| `timestampMs` | не используется: время кадра ставится при получении, как и у Motorica Kart |
| `{ "snapshot": {…} }` | тот же снимок в обёртке — так он лежит в общем хранилище App Group на iOS |

Жестов в снимке нет — только два уровня, которые считает сам Motorica Start (как именно, в коде игры не описано). Поэтому с Motorica Start работают пороговая и пропорциональная схемы. Схеме жестов нужен другой источник. Motorica Kart рулит разностью `closeLevel − openLevel` с мёртвой зоной 8 из 255 и через 500 мс без снимка встаёт на паузу. Сторож «Синергии» — 300 мс.

**Прежний формат (интеграции 2023–2024 годов, `DataTransferToService` в коде Motorica Start):** `{ "sensor_level_1": 51, "sensor_level_2": 255, "open_ch_num": 30, "close_ch_num": 40 }`. Датчик 1 — канал B (раскрытие), датчик 2 — канал A (сжатие): так их сравнивает с порогами протеза встроенный «Арканоид». Единицы не описаны: уровни делятся на 255, как в v1, а калибровка исправит любой масштаб. Пороги протеза `open_ch_num`, `close_ch_num` с 5.29 читаются так же, как ответ `getLatestThresholds()` (ниже).

**Каналы наоборот.** Если источник шлёт A и B в другом порядке, включите «Настройки → Источник сигнала → Поменять каналы A и B» (`swapChannels`). Так делают и игры «Моторики»: инверсия управления есть в Motorica Kart и «Арканоиде». После переключения пройдите калибровку.

На Android игра привязывается к службе Motorica Start: пакет `com.bailout.stickk`, действие `com.motorica.gamecontrol.BIND`, разрешение `com.motorica.gamecontrol.permission.CONTROL_GAME`, обратный вызов `IGameControlCallback`. Пример хоста — `docs/embed/android/MotoricaStartLink.kt`. На iOS снимок лежит в общем хранилище App Group, игру открывают адресом `motorica-stk://`. **Не проверено с настоящим Motorica Start:** у нас нет ни приложения, ни протеза.

**Кого служба пускает (5.29, открытый код Motorica Start).** Публичная ветка `kmm_ubi4_integrationV3` от 20.10.2026 (versionName 3.3.1876) объявляет `CONTROL_GAME` с `protectionLevel="signature"`. Значит, к службе привязывается только приложение, подписанное ключом «Моторики». Стороннему приложению `bind()` вернёт `false`, сколько бы оно ни объявляло разрешение. Реальный путь «Синергии» — подписанный хост «Моторики», который открывает её в WebView и передаёт снимки через `Synergy.feed`. Для этого и сделано встраивание (`docs/embed/README.md`). В той же ветке:
- уровни — байты 0 (раскрытие) и 1 (сжатие) потока датчиков протеза по BLE; служба рассылает их не чаще чем раз в 33 мс, то есть около 30 кадров в секунду. При разрыве Bluetooth приходит `connected: false` и уровни 0/0;
- в конец `IGameControlService` добавлен `getLatestThresholds()` → `[open, close]` 0…255. Это пороги протеза из тех же параметров, что график датчиков Motorica Start. Пока пороги неизвестны, приходит `null`;
- раздел игр знает две игры: Motorica Kart (`com.motorica.games.stk`, карточка из JSON-манифеста на Яндекс Диске и проверка в RuStore) и Subway Surf на Unity (`com.motorica.games.subway`). Игра запускается по имени пакета и активности.

**Пороги протеза (5.29).** Хост передаёт `{ "type": "synergy-thresholds", "openThreshold": 140, "closeThreshold": 90 }` через `Synergy.feed`, `postMessage` или WebSocket. Подходит и ответ службы как есть: `{ "thresholds": [140, 90] }` в порядке `[open, close]`. Это не кадр: сторож и счёт кадров не меняются. Порог сжатия относится к каналу A, порог раскрытия — к B. При «Поменять каналы A и B» пороги меняются вместе с уровнями. Если в настройках включено «Пороги как у протеза» (по умолчанию включено), каждый канал включается на том же уровне сигнала, что и кисть. Порог переводится через калибровку в долю диапазона, не ниже 5 % и не выше 90 % (`PROSTHESIS_THRESHOLDS`). Подстройка покоя линию не сдвигает: это линия протеза в единицах источника. Силы в играх ставятся выше большего из двух порогов. Игра пороги только читает, в протез ничего не пишет. Упражнение на порогах протеза помечено в данных, CSV и отчёте (`thresholds: "prosthesis"`): недели сравниваются честно. Пример хоста на Kotlin вызывает `getLatestThresholds()` после привязки. Если в этой версии Motorica Start метода нет, вызов останется без ответа.

## Митап 21.10.2026: вероятности, два протеза, набор UBI4, запуск упражнения (5.30)

**Поток вероятностей (СППР).** На митапе эксперт «Моторики» сказала, что система распознавания отдаёт поток вероятностей жестов, а выбирается самый вероятный. Кадр может нести `probs` (или `probabilities`, `proba`):

```json
{ "probs": [0.05, 0.10, 0.02, 0.71, 0.04, 0.05, 0.03], "a": 0.4, "b": 0.1 }
{ "probs": { "Neutral": 0.05, "Close": 0.10, "Pinch": 0.71, "Open": 0.14 } }
{ "gesture": "pinch", "confidence": 0.71, "probs": { "rest": 0.05, "pinch": 0.71, "fist": 0.24 } }
```

| Форма | Как читает игра |
|---|---|
| массив | вероятности в порядке классов текущего набора (`CLASS_ORDER`); длина до 64 |
| объект «имя → вероятность» | имена — как в поле `gesture` (id, русское имя, имя Motorica, синоним); порядок не важен |
| `gesture` + `probs` | решает метка, распределение только показывается (так шлёт лаборатория `--lab`) |
| самый вероятный — не из набора | покой с подписью «жест не из набора игры», связь не теряется |

Оценки с суммой больше 1 нормируются; отрицательное или нечисловое значение — не кадр. Под шкалой сигнала — три самых вероятных жеста с шагом 5 %.

**Два протеза.** Кадр с полем `side` (или `hand`): `"left"`, `"right"`, `"l"`, `"r"`, «левый», «правый». Или оба протеза в одном сообщении:

```json
{ "left": { "a": 0.1, "b": 0.0 }, "right": { "a": 0.7, "b": 0.0 } }
{ "sides": { "left": { "openLevel": 12, "closeLevel": 168, "version": 1, "seq": 7 }, "right": { … } } }
```

У каждой стороны свой номер кадра, сторож и, если пришла сырая ЭМГ, своя огибающая. В настройках «Протезы: два» выбирают, какой протез ведёт обычное упражнение; у каждого протеза своя калибровка (`bridge-left`, `bridge-right`). Игра «Две руки» читает оба. Кадры без стороны работают как раньше, пока ни одна сторона не заговорила. Motorica Start держит один протез на сессию (`mDeviceAddress`), а протез сам сообщает сторону (`DeviceInfo.side`), поэтому хосту с двумя протезами достаточно пометить снимок каждого протеза его стороной.

**Набор жестов.** `?gestures=ubi4` (или `synergy`) в адресе, «Настройки → Схема управления → Набор жестов» или переменная окружения `SYNERGY_GESTURE_SET` для тестов. Набор UBI4 — покой и семь жестов обучения Motorica Start в порядке их `GESTURES_ID`: `Neutral`, `ThumbFingers`, `Wrist_Flex`, `Wrist_Extend`, `Close`, `Open`, `Pinch`, `Indication`. Флексия и экстензия — команда «Запястье» (кисть стоит). Сообщение `synergy:ready` называет набор и порядок классов: `"gestures": { "set": "ubi4", "classes": ["rest", "thumbflex", …] }`.

**Открыть упражнение из другого приложения.**
- Android, явный интент: `Intent().setClassName("ru.synergy.trainer", "ru.synergy.trainer.MainActivity").putExtra("game", "grip").putExtra("level", 2).putExtra("gestures", "ubi4")`. `level` — строка или число.
- Android и iOS, ссылка: `synergy://play?game=duo&level=1&gestures=synergy`.
- Значения проверяются по шаблону (игра `[a-z]{2,16}`, уровень 1–99, набор из списка), лишнее отбрасывается. Приложение добавляет `self=1`: это его собственный запуск, а не хост, который ждёт `synergy:close`.

**Качество сигнала.** Хосту ничего делать не нужно: игра сама смотрит на кадры внешнего источника и подсказывает человеку, если помехи, скачки, застывший канал или упор в предел (`src/core/signalquality.js`). В сводке результата этого нет — это сведения о контакте, они идут только в отчёт, который человек сохраняет сам.

## Встраивание в приложение заказчика (5.14, 5.15)

Организатор просит, чтобы решение было «подготовлено с учётом возможности дальнейшей интеграции в стороннее приложение» (страница кейса на Codenrock); скорее всего, это Motorica Start или ATTILAN. «Синергия» встраивается как офлайн-веб-модуль в WebView любого стека из кейса или в `iframe`.

**Полное руководство — [embed/README.md](embed/README.md):** контракт (протокол 1: `synergy:ready`, `synergy:result`, `synergy:close`; команды `synergy-start`, `synergy-frame`, `synergy-ping`), чек-лист и пример для Web, Android (Kotlin), iOS (Swift), Flutter, React Native и Unity, раздел «Как проверено».

Коротко:
- хост → игра: `index.html?game=grip&level=2` (после знакомства с безопасностью на первом запуске), `window.Synergy.start(game, level)`, `window.Synergy.feed(frame)`, а из страницы другого origin — `postMessage`;
- игра → хост: нативный канал своего WebView без внедрённого скрипта (`SynergyHost.onMessage` / `.postMessage`, `webkit.messageHandlers.synergyHost`, `ReactNativeWebView`, `Unity.call`), событие на `document`, `postMessage` родителю — **только** на origin из `?host=https://…`. Хост 5.14 с `SynergyHost.onResult(json)` по-прежнему получает результаты.

Сводка результата (протокол 1):

```json
{ "type": "synergy:result", "protocol": 1, "version": "5.15.0", "at": "2026-10-19T09:12:03.000Z",
  "game": "grip", "level": 2, "scheme": "proportional", "retention": false,
  "score": 84, "stars": 2, "durationS": 61, "skills": { "precision": 81, "switching": 77 } }
```

В сообщениях нет ответов о самочувствии и имени. Сведения о здоровье покидают устройство только в отчёте, который человек сохраняет сам (Прогресс → «Для специалиста»). Демо-упражнения хосту не отправляются. Ошибка хоста не ломает игру.

**Не проверено:** встраивание в настоящий Motorica Start или ATTILAN (их SDK и формат данных не опубликованы). Если хост ждёт другой формат, правится одна функция — `resultMessage()`.

## Транспорты

1. **WebSocket** — Настройки → Источник → «Внешний» → адрес `ws://IP:порт` → «Подключить». Соединение, которое не открылось за 6 с, сбрасывается и повторяется (5.15): статус «нет ответа, повторяем…» — пока мост ни разу не ответил, «переподключение…» — после обрыва.
2. **postMessage** (игра в iframe/WebView): `iframe.contentWindow.postMessage({type:'synergy-frame', a, b}, '<origin игры>')`. С 5.15 первый такой кадр сам включает источник «Внешний» (как `Synergy.feed`), и WebSocket по сохранённому адресу при сигнале от хоста не набирается. С 5.7 кадры принимаются только от встраивающей страницы (`window.parent`), самой страницы или нативного хоста (`WebMessage` без окна-источника): открывшая вкладка или дочернее окно подменить сигнал не могут (`trustedMessageSource`, RT-7).
3. **JS API**: `window.Synergy.feed({a, b, gesture})`; `window.Synergy.useBridge('ws://…')`; `window.Synergy.state()`.
4. **Android**: в `MainActivity.pushFrame(a, b, gesture)` — вызвать из колбэка SDK/BLE протеза.

## Мост `bridge/ws_bridge.py` (Python 3.9+, без зависимостей)

```bash
python3 bridge/ws_bridge.py --demo                 # сценарий: A, B, коактивация
python3 bridge/ws_bridge.py --demo-gestures        # перебор 7 жестов
emulator_cli | python3 bridge/ws_bridge.py --stdin # любой поток "a b" или JSON по строке
pip install -r lab/requirements.txt && python3 bridge/ws_bridge.py --lab
                                                   # сырая 4-канальная ЭМГ → фильтр 20–450 Гц → признаки
                                                   # (RMS, MAV, WL, ZC, SSC) → LDA 7 жестов → игра
python3 bridge/ws_bridge.py --demo --host 0.0.0.0  # чтобы телефон в той же Wi-Fi видел мост
```

**Безопасность моста.** ЭМГ — данные о здоровье, поэтому мост проверяет заголовок `Origin` (защита от перехвата веб-сокета чужим сайтом, OWASP WSTG). Без условий подключаются нативные клиенты (без `Origin`) и страницы с этого же компьютера (`http://127.0.0.1:*`, `http://localhost:*`). Всем остальным — standalone HTML из файла (`Origin: null`), APK, телефону в сети, GitHub Pages — нужен адрес с токеном, который мост печатает при старте: `ws://IP:8765/?token=…` (вставить целиком в Настройки → Источник → адрес). Постоянно доверенный сайт: `--allow-origin https://team.github.io`. Кадр клиента больше 4 КБ или без маски закрывает соединение; кадр источника больше 4 КБ мост пропускает (5.11: на 70 КБ мост падал); клиент, переставший читать, отключается; клиентов не больше 8. Тесты — `python -m unittest bridge/test_ws_bridge.py`.

В режиме `--lab` площадки на экране игры управляют тем, какой жест синтезирует лаборатория (игра отправляет `{"type":"intent", …}`), а распознаёт его настоящий классификатор — с реальными ошибками.

## Калибровка

Настройки → «Калибровка датчиков»: 3 с покоя, 3 с комфортного сжатия (≈70 %), отдых, 3 с раскрытия. Сохраняются покой и комфортный максимум каждого канала (как «чувствительность датчика» в Motorica Start), предупреждения о слабом сигнале и перекрёстных помехах. Калибровка хранится отдельно для экранного эмулятора и внешнего источника.

**Качество канала (5.27, `CALIBRATION_QUALITY`).** Шум покоя считается устойчиво: 1,4826 × медиана абсолютных отклонений покоя. Если комфортное сжатие выше покоя не больше чем на 3 таких шума, канал «плоский» и калибровка не сохраняется. Если 3 шума покоя доходят до уровня выключения канала, игра предупреждает о ложных срабатываниях, но калибровку сохраняет. До 5.27 «плоским» считался канал, где сжатие ниже 1,33 × покоя. Так отказывал любой источник со смещением (покой 1,00 В, сжатие 1,20 В) и проходил канал, где сжатие едва отличалось от шума.

**Подстройка покоя** (ко-адаптивная калибровка, `RestTracker` в `src/core/calibration.js`, параметры `CALIBRATION_ADAPT` в `src/config.js`): во время упражнения с внешним источником уровень покоя медленно следует за дрейфом сигнала — только в подтверждённом покое и не дальше 20 % диапазона. Итог сессии сохраняется в `calibrations.bridge` (поле `adaptedAt`). Большой дрейф или канал, «залипший» во включённом состоянии, — повод перекалибровать: игра скажет об этом в итогах. «Проверка навыка» идёт без подстройки, чтобы результаты недели были сравнимы.

## Электробезопасность самодельных датчиков (5.27)

Электроды на коже — это контакт с телом человека. У платы любителя нет развязки от сети, поэтому питание — только батарея: беспроводной датчик работает от своей батареи, а датчик на проводе к компьютеру или телефону — только пока это устройство отключено от зарядного устройства. Для медицинских изделий ток утечки через электроды ограничивает IEC 60601-1, а у самодельной платы такой проверки нет. Протез и сертифицированные датчики подключаются по инструкции производителя. Это же предупреждение игра показывает в «Настройки → Источник сигнала → Внешний» (`ELECTRICAL_SAFETY` в `src/core/wellbeing.js`).

## Bluetooth-датчики (v5)

Настройки → Источник «Внешний» → «Bluetooth-датчик (BLE UART)». Сервис Nordic UART `6e400001-…`, уведомления TX `6e400003-…`, строки `"a b\n"` / `"a,b\n"` / JSON — тот же `parseExternal()`. Куски по 20 байт склеиваются (`LineAssembler`), мусор без перевода строки > 512 символов отбрасывается, при обрыве — 3 попытки переподключения. После подключения обязательна калибровка (сырые единицы АЦП 0..4095). Прошивка-пример: `bridge/firmware/esp32_emg_ble/` (ESP32 + 2 × MyoWare 2.0, 50 Гц; **не компилировалась командой**). Web Bluetooth: Chrome/Edge на Android и ПК; не в iOS Safari и не в Android WebView — там `pushFrame()`.

## Нативный мост Android (v5)

`window.SynergyNative.speak(text, interrupt)`, `.stop()`, `.share(name, mime, text)` (системное «Поделиться» вместо скачивания — WebView не умеет blob-загрузки), `.print(title, html)` (PrintManager → «Сохранить как PDF»). Доступен только страницам из `android_asset` (внешняя навигация заблокирована).
