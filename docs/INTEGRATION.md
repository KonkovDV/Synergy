# Подключение эмулятора организаторов, датчиков или протеза

## Контракт кадра (SignalFrame)

```json
{ "a": 0.42, "b": 0.05, "gesture": "pinch", "confidence": 0.91, "effort": 0.6 }
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `a`, `b` | да (для жестов можно опустить) | огибающая ЭМГ каналов A (сжатие) и B (раскрытие), ≥ 0, лучше ≥ 20 кадров/с. Если не 0..1 — выполните калибровку. **Сырая (двуполярная) ЭМГ** распознаётся по первому отрицательному значению: дальше каждое сообщение входит в RMS-огибающую за 150 мс (`EnvelopeFilter`), в статусе — «сырая ЭМГ → огибающая». Для честной огибающей сырой сигнал нужен с частотой ≥ 500 Гц; лучше присылать готовую огибающую |
| `gesture` | нет | id (`rest, fist, open, pinch, point, key, thumb`), русское имя (`Кулак`, `щепоть`…, регистр не важен), индекс класса 0–6 (`CLASS_ORDER`) или синоним (`close`, `palm`, `tripod`, `lateral`…). Имена обучения жестам UBI4 из Motorica Start (`Neutral`, `Close`, `Open`, `Pinch`, `Indication` и подписи его экрана) понимаются с 5.29. **Класс не из набора** (`Wrist_Flex`, индекс 7…) — покой с уверенностью 0, связь не теряется; под полем — «жест не из набора игры: …» |
| `confidence` | нет | уверенность классификатора 0..1; ниже 0,6 → «покой» |
| `effort` | нет | сила жеста 0..1 (иначе берётся max(a, b)) |

Время кадра проставляется **при получении** — часы источника не важны. Если 300 мс нет кадров — упражнение замирает.

Принимаются и другие формы: `{ch:[a,b]}`, `{channels:[…]}`, `{emg:[…]}`, `[a,b]`, строка `"a b"`/`"a,b"` (пустая строка — не кадр, 5.11), `{class|label: …, prob|p: …}`. Калибровка работает в любых единицах источника (вольты, отсчёты АЦП). Номера каналов для A/B в многоканальном массиве задаются в `parseExternal(msg, {channelA, channelB})`.

**Когда 28.10 опубликуют эмулятор:** изменить только `src/input/bridge.js → parseExternal()` (+ тест в `tests/core.test.mjs`). Если эмулятор — программа с выводом в консоль, используйте `--stdin` без изменения кода игры.

### Снимок Motorica Start (контракт v1, 5.21)

Так Motorica Start передаёт сигнал своей игре Motorica Kart. Контракт открыт в её исходном коде: [HakerFromRussia-XD/1_game_stk](https://github.com/HakerFromRussia-XD/1_game_stk) (`GameControlSnapshot.java`, `IGameControlService.aidl`, `motorica_game_control.cpp`; «Motorica-maintained SuperTuxKart fork for Motorica Start controller integration»). «Синергия» принимает снимок как есть, через любой транспорт выше:

```json
{ "version": 1, "seq": 1842, "timestampMs": 1792540800000, "openLevel": 12, "closeLevel": 168, "connected": true }
```

| Поле | Как читает «Синергия» |
|---|---|
| `closeLevel` | канал A (сжатие): 0…255 → 0…1 |
| `openLevel` | канал B (раскрытие): 0…255 → 0…1 |
| `connected: false` | протез не на связи: последний кадр сбрасывается, через 300 мс — «нет сигнала» и пауза. Уровни 0/0 при этом не считаются покоем |
| `seq` | тот же номер — не новый кадр. Хост, который пересылает последний снимок каждые 33 мс, не продлевает жизнь остановившемуся устройству |
| `version` | только 1: другая версия может означать другие уровни |
| `timestampMs` | не используется: время кадра ставится при получении, как и у Motorica Kart |
| `{ "snapshot": {…} }` | тот же снимок в обёртке — так он лежит в общем хранилище App Group на iOS |

Жестов в снимке нет — только два уровня, которые считает сам Motorica Start (как именно, в коде игры не описано). Поэтому с Motorica Start работают пороговая и пропорциональная схемы. Схеме жестов нужен другой источник. Motorica Kart рулит разностью `closeLevel − openLevel` с мёртвой зоной 8 из 255 и через 500 мс без снимка встаёт на паузу. Сторож «Синергии» — 300 мс.

**Прежний формат (интеграции 2023–2024 годов, `DataTransferToService` в коде Motorica Start):** `{ "sensor_level_1": 51, "sensor_level_2": 255, "open_ch_num": 30, "close_ch_num": 40 }`. Датчик 1 — канал B (раскрытие), датчик 2 — канал A (сжатие): так их сравнивает с порогами протеза встроенный «Арканоид». Единицы не описаны: уровни делятся на 255, как в v1, а калибровка исправит любой масштаб. Пороги протеза `open_ch_num`, `close_ch_num` с 5.29 читаются так же, как ответ `getLatestThresholds()` (ниже).

**Каналы наоборот.** Если источник шлёт A и B в другом порядке, включите «Настройки → Источник сигнала → Поменять каналы A и B» (`swapChannels`). Так делают и игры «Моторики»: инверсия управления есть в Motorica Kart и «Арканоиде». После переключения пройдите калибровку.

На Android игра привязывается к службе Motorica Start: пакет `com.bailout.stickk`, действие `com.motorica.gamecontrol.BIND`, разрешение `com.motorica.gamecontrol.permission.CONTROL_GAME`, обратный вызов `IGameControlCallback`. Пример хоста — `docs/embed/android/MotoricaStartLink.kt`. На iOS снимок лежит в общем хранилище App Group, игру открывают адресом `motorica-stk://`. **Не проверено с настоящим Motorica Start:** у нас нет ни приложения, ни протеза.

**Кого служба пускает (5.29, открытый код Motorica Start).** Публичная ветка `kmm_ubi4_integrationV3` от 20.10.2026 (versionName 3.3.1876) объявляет `CONTROL_GAME` с `protectionLevel="signature"`. Значит, к службе привязывается только приложение, подписанное ключом «Моторики». Стороннему приложению `bind()` вернёт `false`, сколько бы оно ни объявляло разрешение. До 04.11.2026 здесь было написано, что реальный путь «Синергии» — подписанный хост «Моторики», который открывает её в WebView. **Ответы организаторов 04.11.2026 (№ 15) это поправили:** «встраивание» — интеграция запуска и обмена данными, а не размещение игрового компонента внутри хост-приложения; интеграция — роутингом. Основной путь теперь такой же, как у игр самой «Моторики» (ниже, «Как Motorica Start запускает игры»): Motorica Start открывает APK «Синергии» явным интентом или ссылкой `synergy://play`, а обмен идёт через её службу. Чтобы служба пустила «Синергию», «Моторика» должна разрешить её подпись — как своим играм. WebView и iframe (`docs/embed/README.md`) остаются запасным путём для хостов, которые хотят держать игру у себя. В той же ветке:
- уровни — байты 0 (раскрытие) и 1 (сжатие) потока датчиков протеза по BLE; служба рассылает их не чаще чем раз в 33 мс, то есть около 30 кадров в секунду. При разрыве Bluetooth приходит `connected: false` и уровни 0/0;
- в конец `IGameControlService` добавлен `getLatestThresholds()` → `[open, close]` 0…255. Это пороги протеза из тех же параметров, что график датчиков Motorica Start. Пока пороги неизвестны, приходит `null`;
- **25.10.2026, ветка `kmm_ubi4_with_clean_arch`** (перенос Motorica Start на Kotlin Multiplatform с общим модулем для iOS, последний push 20.10.2026). Её `IGameControlService.aidl` — три метода, **без `getLatestThresholds()`**: ветка взяла `kmm_ubi4_integrationV3` 28.09, а метод там появился 14.10. Если перенос сольют таким, пороги протеза перестанут приходить. Пример хоста к этому готов: `transact()` вернёт `false`, игра останется на своих порогах (`docs/embed/android/MotoricaStartLink.kt`).
- **iOS, тот же открытый код** (`GameControlBroadcaster.swift`, с 06.08.2026). Снимок — словарь под ключом `snapshot` в общем `UserDefaults` группы приложений: `version` 1, `seq`, `timestampMs`, `openLevel`, `closeLevel` (0…255), `connected`. Не чаще 30 раз в секунду, при разрыве — сразу `connected: false` и 0/0. Группа берётся из ключа `MotoricaGameControlAppGroup` в `Info.plist`, то есть подпись команды «Моторики». Перед запуском игры пишется «аренда» `launchRequest.stk.v1` (`version`, `token`, `timestampMs`, `scheme`), игра открывается адресом `<scheme>://launch`. На 25.10 принималась только схема `motorica-stk`; с 05.11 игры iPhone берутся из каталога (пункт «Каталог игр» ниже), и схему игры называет запись каталога. **Порогов в снимке iOS нет**: «Пороги как у протеза» на iPhone работают, только если хост передаст их сам. Повтор снимка с тем же `seq` игра не считает новым кадром, поэтому застывший снимок закрытого приложения доходит до сторожа 300 мс.
- раздел игр знает две игры: Motorica Kart (`com.motorica.games.stk`, карточка из JSON-манифеста на Яндекс Диске и проверка в RuStore) и Subway Surf на Unity (`com.motorica.games.subway`). Игра запускается по имени пакета и активности.
- **Каталог игр (OSINT 06.11.2026, коммиты Motorica Start от 05.11 в той же ветке).** Список игр раздела больше не зашит в приложение: Android и iOS читают один публичный JSON-каталог `{"games": [...]}` с сервера «Моторики». Запись игры — `id`, `title` и объект платформы. Android: `packageName`, `launcherActivity` (полное имя класса для `setClassName`), `versionName`, `versionCode` (целое, сравнивается с установленным APK: больше — «Обновить»), необязательный `usesMotoricaControl` (тогда в интент кладётся `motorica_ms_control=true`). iOS: `bundleId`, `urlScheme`, `versionName`, целый `versionCode` (`CFBundleVersion`), `appStoreUrl` (пустой, пока игры нет в App Store). Не установлена — Android ведёт в RuStore по имени пакета. На iPhone игра открывается адресом `<urlScheme>://launch`; если её схемы нет в `LSApplicationQueriesSchemes` Motorica Start, приложение не может проверить установку и показывает «Открыть» со статусом «неизвестно» — открыть такую игру всё равно можно. Токен запуска (`?token=`) получают только игры с `requiresLaunchToken`: его проверяют через общую группу приложений «Моторики». Subway Surf с экрана Android убран; в каталоге — гоночная игра `stk` (пакет `com.motorica.games.stk`, бывшая Motorica Kart; в их тестах и на iPhone она называется Fluxara Drift) и Sushi Dash. **Что сделано у нас:** готовая запись «Синергии» в этой схеме — `docs/embed/motorica-start-catalog.json`: `ru.synergy.trainer` / `ru.synergy.trainer.MainActivity`, `versionCode` APK и номер сборки iPhone, `urlScheme` `synergy`, `usesMotoricaControl: false` (служба управления пускает только подпись «Моторики», обещать её нечем). Тест сверяет запись с `AndroidManifest.xml`, `ios/project.yml` и правилами их разборщика (`tests/v621.test.mjs`). Оболочка iPhone принимает `synergy://launch` как обычный запуск — главный экран, как APK, открытый по активности. Чтобы «Синергия» появилась в разделе игр, «Моторике» достаточно добавить эту запись в каталог; для кнопки «Скачать» на Android APK нужен в RuStore.
- **Как Motorica Start запускает игры (OSINT 04.11.2026, ветка `kmm_ubi4_integrationV3`, `AccountGamesFragment.kt`).** Сначала поднимается служба `GameControlBridgeService` (foreground), затем `Intent().setClassName(package, launcherActivity).addFlags(FLAG_ACTIVITY_NEW_TASK)`. Играм на Unity — Subway (`com.motorica.games.subway`) и новой третьей Sushi (`com.unity.trashdash`) — добавляется `putExtra("motorica_ms_control", true)`. **Стороны руки и порогов в интенте нет**: пороги игра берёт из службы (`getLatestThresholds()`), сторону руки не передаёт никто. В ветке переноса на KMM (`kmm_ubi4_with_clean_arch`, коммит 03.11) `getLatestThresholds()` по-прежнему нет. APK «Синергии» принимает такой запуск: `ru.synergy.trainer.MainActivity` экспортирована, extras `game`, `level`, `gestures` необязательны. Ответ организаторов № 16 называет входом игры сторону руки, пороги и поток, а возвратом — чувствительность и пороги. В параметрах запуска игра пока не принимает ни стороны, ни порогов и не возвращает их хосту: имена ключей не определены ни в задании, ни в открытом коде, поэтому это вопрос на чек-пойнт 5.11 (`PLAN.md`, «Сессия Q&A 04.11»).

**Пороги протеза (5.29).** Хост передаёт `{ "type": "synergy-thresholds", "openThreshold": 140, "closeThreshold": 90 }` через `Synergy.feed`, `postMessage` или WebSocket. Подходит и ответ службы как есть: `{ "thresholds": [140, 90] }` в порядке `[open, close]`. Это не кадр: сторож и счёт кадров не меняются. Порог сжатия относится к каналу A, порог раскрытия — к B. При «Поменять каналы A и B» пороги меняются вместе с уровнями. Если в настройках включено «Пороги как у протеза» (по умолчанию включено), каждый канал включается на том же уровне сигнала, что и кисть. Порог переводится через калибровку в долю диапазона, не ниже 5 % и не выше 90 % (`PROSTHESIS_THRESHOLDS`). Подстройка покоя линию не сдвигает: это линия протеза в единицах источника. Силы в играх ставятся выше большего из двух порогов. Игра пороги только читает, в протез ничего не пишет. Упражнение на порогах протеза помечено в данных, CSV и отчёте (`thresholds: "prosthesis"`): недели сравниваются честно. Пример хоста на Kotlin вызывает `getLatestThresholds()` после привязки. Если в этой версии Motorica Start метода нет, вызов останется без ответа.

**Четыре значения в одном сообщении (ответ организаторов № 6; перенесено 06.11.2026 из параллельной ветки).** «В игру поступают четыре значения: амплитуды двух ЭМГ-сенсоров 0–255 и два пороговых значения». Такое сообщение — кадр с порогами: `{ "openLevel": 120, "closeLevel": 40, "thresholds": [80, 90] }`, `{ "openLevel": …, "closeLevel": …, "openThreshold": …, "closeThreshold": … }`, `{ "a": 200, "b": 30, "thresholds": [60, 70] }` или `{ "emg": [200, 30], "thresholds": [60, 70] }`. Уровни — кадр (сторож доволен), пороги — рядом; о смене порогов игра узнаёт один раз. В общем кадре с порогами обе пары — в шкале 0–255 контракта и масштабируются одинаково: порог остаётся ниже своего уровня. До 06.11 пороги в одном сообщении с уровнями «побеждали»: игра видела только пороги и показывала «нет сигнала». Пороги без уровней — по-прежнему не кадр; кривой порог отбрасывает всё сообщение (`tests/qa0611.test.mjs`).

## Митап 21.10.2026: вероятности, два протеза, набор UBI4, запуск упражнения (5.30)

**Поток вероятностей (СППР).** На митапе эксперт «Моторики» сказала, что система распознавания отдаёт поток вероятностей жестов, а выбирается самый вероятный. Кадр может нести `probs` (или `probabilities`, `proba`):

```json
{ "probs": [0.05, 0.10, 0.02, 0.71, 0.04, 0.05, 0.03], "a": 0.4, "b": 0.1 }
{ "probs": { "Neutral": 0.05, "Close": 0.10, "Pinch": 0.71, "Open": 0.14 } }
{ "gesture": "pinch", "confidence": 0.71, "probs": { "rest": 0.05, "pinch": 0.71, "fist": 0.24 } }
```

| Форма | Как читает игра |
|---|---|
| массив | вероятности в порядке классов текущего набора (`CLASS_ORDER`); длина до 64 |
| объект «имя → вероятность» | имена — как в поле `gesture` (id, русское имя, имя Motorica, синоним); порядок не важен |
| `gesture` + `probs` | решает метка, распределение только показывается (так шлёт лаборатория `--lab`) |
| самый вероятный — не из набора | покой с подписью «жест не из набора игры», связь не теряется |

Оценки с суммой больше 1 нормируются; отрицательное или нечисловое значение — не кадр. Под шкалой сигнала — три самых вероятных жеста с шагом 5 %.

**Два протеза.** Кадр с полем `side` (или `hand`): `"left"`, `"right"`, `"l"`, `"r"`, «левый», «правый». Или оба протеза в одном сообщении:

```json
{ "left": { "a": 0.1, "b": 0.0 }, "right": { "a": 0.7, "b": 0.0 } }
{ "sides": { "left": { "openLevel": 12, "closeLevel": 168, "version": 1, "seq": 7 }, "right": { … } } }
```

У каждой стороны свой номер кадра, сторож и, если пришла сырая ЭМГ, своя огибающая. В настройках «Протезы: два» выбирают, какой протез ведёт обычное упражнение; у каждого протеза своя калибровка (`bridge-left`, `bridge-right`). Игра «Две руки» читает оба. Кадры без стороны работают как раньше, пока ни одна сторона не заговорила. Motorica Start держит один протез на сессию (`mDeviceAddress`), а протез сам сообщает сторону (`DeviceInfo.side`), поэтому хосту с двумя протезами достаточно пометить снимок каждого протеза его стороной.

**Набор жестов.** По умолчанию `tz` — словарь ТЗ. Ещё `?gestures=tz2` (СПППР «2 жеста + нейтраль», ответы 04.11), `synergy`, `ubi4` или `spr8` в адресе, в ссылке `synergy://play` и в extras APK, «Настройки → Схема управления → Набор жестов» или переменная окружения `SYNERGY_GESTURE_SET` для тестов. Набор UBI4 — покой и семь жестов обучения Motorica Start в порядке их `GESTURES_ID`: `Neutral`, `ThumbFingers`, `Wrist_Flex`, `Wrist_Extend`, `Close`, `Open`, `Pinch`, `Indication`. Флексия и экстензия — команда «Запястье» (кисть стоит). Сообщение `synergy:ready` называет набор и порядок классов: `"gestures": { "set": "ubi4", "classes": ["rest", "thumbflex", …] }`.

**Открыть упражнение из другого приложения.**
- Android, явный интент: `Intent().setClassName("ru.synergy.trainer", "ru.synergy.trainer.MainActivity").putExtra("game", "grip").putExtra("level", 2).putExtra("gestures", "ubi4")`. `level` — строка или число.
- Android и iOS, ссылка: `synergy://play?game=duo&level=1&gestures=synergy`.
- Значения проверяются по шаблону (игра `[a-z]{2,16}`, уровень 1–99, набор из списка), лишнее отбрасывается. Приложение добавляет `self=1`: это его собственный запуск, а не хост, который ждёт `synergy:close`.

**Рука и пороги при запуске, пороги обратно (6.1, ответы организаторов 04.11, № 15–16).** «Motorica Start передаёт игре сторону руки, пороги и поток двух ЭМГ-датчиков; игра может вернуть чувствительность и пороги». Ключи — наши: в открытом коде Motorica Start запуск их пока не передаёт (вопрос К.3, `PLAN.md`). Одни и те же шаблоны в адресе страницы (`src/services/host.js`), в extras интента и ссылке Android (`MainActivity.launchQuery`) и в ссылке iPhone (`LaunchRequest`):

| Ключ | Значение | Что делает игра |
|---|---|---|
| `side` | `left` или `right` | рука с протезом: сохраняется в настройках, как если бы её выбрал человек (приложение протеза знает её точно) |
| `closeThreshold`, `openThreshold` | целые 0–255, только парой — единицы `getLatestThresholds()` и снимка v1 | пороги протеза для внешнего источника, пока хост не пришлёт свои (`synergy-thresholds`); источник они не переключают — APK, открытый интентом, потока от хоста ещё не получает |

```kotlin
Intent().setClassName("ru.synergy.trainer", "ru.synergy.trainer.MainActivity")
    .putExtra("game", "grip").putExtra("level", 2)
    .putExtra("side", "left").putExtra("closeThreshold", 60).putExtra("openThreshold", 45)  // числа или строки
```

Ссылка: `synergy://play?game=grip&level=2&side=left&closeThreshold=60&openThreshold=45`.

Обратно — в `synergy:result` поле `channels`, если упражнение шло на внешнем источнике (экранный эмулятор — не ЭМГ человека, тогда поля нет):

```json
"channels": { "closeThreshold": 53, "openThreshold": 64, "line": "game", "sensitivity": { "close": 0.22, "open": 0.3 } }
```

`closeThreshold`/`openThreshold` — где каналы включались в этом упражнении, в тех же 0–255, что приходят от хоста: покой + доля × (максимум − покой) калибровки игры, × 255. `line` — чья это линия: ползунков игры (`game`) или порогов протеза (`prosthesis`). `sensitivity` — ползунки игры «Порог закрытия (A)» и «Порог открытия (B)», доля откалиброванного диапазона. **Это порог, а не «чувствительность датчика» приложения протеза:** там чувствительность — отдельный параметр рядом с порогом (на митапе: порог 109, чувствительность 25), по ответу 07.11 № 12 от неё зависит нужное усилие. Хосту не стоит записывать `sensitivity` в настройку чувствительности протеза. Что приложение ждёт под этим словом и в каких единицах — вопрос 3 чек-пойнта 09.11; до ответа имя поля не меняется. В протез игра ничего не пишет: что делать с числами — решает хост. Проверка — `tests/launch.test.mjs`, `tests/app.test.mjs`, `tests/v530.test.mjs` (javac и обвязка), `VERIFY_API=1 sh tools/build-apk.sh`.

**Настройки обратно, без упражнения (06.11.2026, ответ № 16).** Пороги можно поменять в настройках и не сыграть ни одного упражнения — тогда `synergy:result` их не донесёт. Поэтому игра шлёт `synergy:settings`, когда меняется порог, сторона или «Пороги как у протеза» (через 0,6 с после последнего движения ползунка), и перед `synergy:close`:

```json
{ "type": "synergy:settings", "protocol": 1, "version": "6.3.1", "side": "left",
  "sensitivity": { "close": 0.22, "open": 0.3 }, "prosthesisThresholds": true,
  "channels": { "closeThreshold": 53, "openThreshold": 64, "line": "game", "sensitivity": { "close": 0.22, "open": 0.3 } } }
```

`channels` — те же числа, что в результате, и только на внешнем источнике. Имени и ответов о самочувствии в сообщении нет. Проверка — `tests/qa0611.test.mjs`.

**Качество сигнала.** Хосту ничего делать не нужно: игра сама смотрит на кадры внешнего источника и подсказывает человеку, если помехи, скачки, застывший канал или упор в предел (`src/core/signalquality.js`). В сводке результата этого нет — это сведения о контакте, они идут только в отчёт, который человек сохраняет сам.

**Активные пользователи (5.31, метрика компании).** Игра офлайн и ничего никуда не отправляет. Хост, в который она встроена, уже получает `synergy:result` после каждого упражнения: поле `at` — когда, `durationS` — сколько секунд. Активный день — день, в который у этого человека есть хотя бы один такой результат. Считать людей и дни хост может у себя. В игру аналитику не добавляем.

## Поток СПППР по ТЗ 28.10 (6.0)

Пакет задания, одна строка JSON на пакет:

```json
{"timestamp_ms": 1720000000123, "dist": {"neutral": 0.05, "flexion": 0.65, "extension": 0.15, "pronation": 0.05, "supination": 0.05, "adduction": 0.03, "abduction": 0.02}}
```

| Правило ТЗ | Как читает игра (`src/core/spppr.js`) |
|---|---|
| Контракт жёсткий | `parseSppprPacket`: целое `timestamp_ms` ≥ 0; ключи `dist` — семь состояний ТЗ при любом словаре СПППР (ответ экспертов 07.11, № 1: структура потока не меняется; пакет ровно из трёх ключей тоже принимается, ниже) со значениями 0…1, сумма 1 ± 0,02 (после проверки нормируется). **6.3.1:** если все значения пакета лежат на шаге 0,1 или 0,01 (распознаватель округляет и не подгоняет сумму), сумма может отличаться от 1 на число ключей × половину шага — до 0,035 при двух знаках, до 0,35 при одном (`sumToleranceOf`); шаг последнего пакета — `stats.decimals` декодера. Иначе пакет отклонён, причина (`json`, `timestamp`, `missing`, `unknown`, `value`, `sum`…) — в счётчиках и в строке потока. Лишние поля верхнего уровня не мешают (например, номер пакета) |
| `timestamp_ms` — таймер МК | dt — только разность `timestamp_ms` соседних пакетов. Повтор и пакет из прошлого отбрасываются (`stale`), откат больше чем на 1 с — перезапуск МК: декодер начинает заново. Смещение часов телефона и МК — нижняя огибающая «приход − timestamp» последних 64 пакетов; нужно только чтобы рисовать между пакетами |
| Softmax, доли вероятностей | вероятности сглаживаются экспонентой (45 мс по времени МК); оси x = flexion − extension, y = pronation − supination, z = abduction − adduction (знаки — `axis` в `vocabulary.js`); мёртвая зона 0,10; команда — доминирующая ось (вход 0,18, выход 0,10, выдержка 50 мс), чёткость — величина оси за мёртвой зоной. Вероятность — сходство с паттерном, не сила (ответ экспертов 07.11, № 3): в играх сила хвата и высота набираются временем удержания жеста, скорость растёт с чёткостью до 0,55 (`SPPPR.fullSpeedAt`). Сложных жестов СПППР не распознаёт (ответ № 4): движется ось команды, доля второй пары — «смешанный жест» |
| Jitter 10–100+ мс | между пакетами оси продолжаются по наклону, не дальше 100 мс; рывка нет и при 100+ мс |
| Packet Loss > 200 мс | скорость гаснет экспонентой с постоянной 120 мс; упражнение идёт. Через 1,5 с тишины — «сигнал потерян» и пауза «Сигнал потерян» (ответ № 25: больше 1–2 с — критично); продолжить — кнопкой; после возврата движение начинается с нейтрали |
| Прощать единичные шумы | смена направления — только если сглаженное значение и последний пакет согласны, и это держится 50 мс по часам МК; прощённые выбросы считаются. Выбросы СПППР не фильтрует (ответ экспертов 07.11, № 2) — поэтому на номинальных 10 Гц команда приходит по второму пакету, через 100 мс после первого |
| Частота и задержка | 10 Гц — номинальная частота; задержка до 100 мс включает работу СПППР и передачу (ответы 04.11 № 24 и 07.11 № 2). Экранный эмулятор шлёт 10 Гц по умолчанию, 50 Гц — по настройке «Частота пакетов»; программа — `--rate 10` (по умолчанию) или `--rate 50` |

**Два словаря СПППР (ответы организаторов 04.11, № 22; экспертов 07.11, № 1).** СПППР бывает «6 жестов + нейтраль» и «2 жеста + нейтраль». Структура потока при этом не меняется: пакет второго несёт те же семь ключей, у четырёх классов, которых устройство не знает, — 0:

```json
{"timestamp_ms": 1720000000123, "dist": {"neutral": 0.2, "flexion": 0.7, "extension": 0.1, "pronation": 0, "supination": 0, "adduction": 0, "abduction": 0}}
```

Какие два жеста, в ответах не сказано: берём сгибание и разгибание — антагонисты, на которых ТЗ строит тренировку и джойстик. Словарь устройства декодер узнаёт по значениям: softmax семи классов не даёт точного нуля, поэтому 30 пакетов упражнения подряд с нулями у четырёх движений запястья — это «2 жеста + нейтраль» (`DICTIONARY_MIN_PACKETS`). Пакет ровно из трёх ключей (`neutral`, `flexion`, `extension`) тоже принимается — так игра читала ответ № 22 до 07.11; строгость та же: набор ключей — ровно один словарь, иначе `missing` (первый недостающий ключ ближайшего словаря) или `unknown`. Словарь потока — в счётчиках, в записи упражнения (`stream.classes`, число ключей — `stream.keys`), в CSV (`stream_classes`) и в отчёте специалиста. Для неё есть набор жестов «СПППР · 2 жеста» (`tz2`, адрес `?gestures=tz2`, extra `gestures` интента): игры, «Первые шаги» и проверка навыка идут на двух жестах, экранный эмулятор шлёт семь ключей с нулями у незнакомых классов. Если поток знает меньше классов, чем набор игры, строка потока подсказывает нужный набор. Эмулятор-программа: `node tools/spppr-emulator.mjs --classes 3`. Проверка: `npm run test:tz` — все уровни четырёх игр в трёх схемах на обоих словарях.

Каналы для двух схем: A = вероятность сгибания, B = вероятность разгибания — пороговая и пропорциональная схемы работают и на этом потоке, в том числе на словаре «2 жеста + нейтраль». В схеме жестов сгибание закрывает кисть, разгибание раскрывает, пронация, супинация, приведение и отведение двигают запястье (кисть стоит), а джойстик виден под полосами сигнала.

**Транспорт.** Пакет узнаётся в любом транспорте (`parseExternal` → `{ spppr }`): WebSocket, `postMessage({type: 'synergy-frame', …пакет})`, `window.Synergy.feed(text)`, Android `pushFrame`. Мост: `node tools/spppr-emulator.mjs | python3 bridge/ws_bridge.py --stdin` (каждый пакет уходит один раз, в порядке прихода) или `python3 bridge/ws_bridge.py --lab --spppr` (решения LDA пакетами ТЗ).

**Замена эмулятора на драйвер МК — одна строка** в `src/input/spppr-driver.js`:

```js
export const createSppprDriver = o => new EmulatorDriver(new SppprEmulator(o));            // эмулятор (по умолчанию)
// export const createSppprDriver = o => new WebSocketDriver({ url: 'ws://192.168.4.1:81' }); // МК по Wi-Fi
// export const createSppprDriver = o => new WebSerialDriver({ baudRate: 115200 });            // МК по USB/UART
// export const createSppprDriver = o => new BleNusDriver();                                   // МК по BLE (NUS)
```

Драйвер — объект `start(onPacket)` / `stop()`, где `onPacket(text, arrivalMs)` получает строку контракта; всё остальное (разбор, часы МК, джойстик) — в декодере. Драйверы WebSocket, Web Serial, BLE NUS и хоста — `src/input/spppr-drivers.js`; с настоящим МК они не проверены (`LIMITS.md`).

**Эмулятор** (`src/input/spppr-emulator.js`, `tools/spppr-emulator.mjs --help`): словарь устройства — семь состояний или «2 жеста + нейтраль» (`--classes 3`: ключей всё равно семь, у незнакомых классов нули; движения вне словаря он не распознаёт вовсе, даже ошибочным пакетом), одно движение за раз (сложных жестов СПППР не распознаёт — ответ экспертов 07.11, № 4), таймер МК со старта устройства, частота 10 Гц — номинальная, по умолчанию — или 50 Гц (`--rate 50`, в игре — «Частота пакетов»), интервалы лог-нормально вокруг выбранной частоты: среднее равно периоду (50 Гц — 20 мс, 10 Гц — 100 мс), на 50 Гц не короче 10 мс, на 10 Гц не короче половины периода и может тянуться дольше 100 мс, пачки после замирания радио, потери (до 3 %), обрывы 220–520 мс, одиночные ошибочные пакеты и путаницы классов с общими мышцами, рост и спад вероятности при сокращении (≈ 70 и 110 мс), по флагам — перезапуск МК и битые пакеты. Детерминирован для зерна.

## Встраивание в приложение заказчика (5.14, 5.15)

Организатор просит, чтобы решение было «подготовлено с учётом возможности дальнейшей интеграции в стороннее приложение» (страница кейса на Codenrock); скорее всего, это Motorica Start или ATTILAN. «Синергия» встраивается как офлайн-веб-модуль в WebView любого стека из кейса или в `iframe`.

**Полное руководство — [embed/README.md](embed/README.md):** контракт (протокол 1: `synergy:ready`, `synergy:result`, `synergy:settings`, `synergy:close`; команды `synergy-start`, `synergy-frame`, `synergy-ping`), чек-лист и пример для Web, Android (Kotlin), iOS (Swift), Flutter, React Native и Unity, раздел «Как проверено».

Коротко:
- хост → игра: `index.html?game=grip&level=2` (после знакомства с безопасностью на первом запуске), `window.Synergy.start(game, level)`, `window.Synergy.feed(frame)`, а из страницы другого origin — `postMessage`;
- игра → хост: нативный канал своего WebView без внедрённого скрипта (`SynergyHost.onMessage` / `.postMessage`, `webkit.messageHandlers.synergyHost`, `ReactNativeWebView`, `Unity.call`), событие на `document`, `postMessage` родителю — **только** на origin из `?host=https://…`. Хост 5.14 с `SynergyHost.onResult(json)` по-прежнему получает результаты.

Сводка результата (протокол 1):

```json
{ "type": "synergy:result", "protocol": 1, "version": "5.15.0", "at": "2026-10-19T09:12:03.000Z",
  "game": "grip", "level": 2, "scheme": "proportional", "retention": false,
  "score": 84, "stars": 2, "durationS": 61, "skills": { "precision": 81, "switching": 77 } }
```

В сообщениях нет ответов о самочувствии и имени. Сведения о здоровье покидают устройство только в отчёте, который человек сохраняет сам (Прогресс → «Для специалиста»). Демо-упражнения хосту не отправляются. Ошибка хоста не ломает игру.

**Не проверено:** встраивание в настоящий Motorica Start или ATTILAN (их SDK и формат данных не опубликованы). Если хост ждёт другой формат, правится одна функция — `resultMessage()`.

## Транспорты

1. **WebSocket** — Настройки → Источник → «Внешний» → адрес `ws://IP:порт` → «Подключить». Соединение, которое не открылось за 6 с, сбрасывается и повторяется (5.15): статус «нет ответа, повторяем…» — пока мост ни разу не ответил, «переподключение…» — после обрыва.
2. **postMessage** (игра в iframe/WebView): `iframe.contentWindow.postMessage({type:'synergy-frame', a, b}, '<origin игры>')`. С 5.15 первый такой кадр сам включает источник «Внешний» (как `Synergy.feed`), и WebSocket по сохранённому адресу при сигнале от хоста не набирается. С 5.7 кадры принимаются только от встраивающей страницы (`window.parent`), самой страницы или нативного хоста (`WebMessage` без окна-источника): открывшая вкладка или дочернее окно подменить сигнал не могут (`trustedMessageSource`, RT-7).
3. **JS API**: `window.Synergy.feed({a, b, gesture})`; `window.Synergy.useBridge('ws://…')`; `window.Synergy.state()`; `window.Synergy.rememberDays([{day, seconds, runs}])` — только для проверки раскладки, до 30 дней.
4. **Android**: в `MainActivity.pushFrame(a, b, gesture)` — вызвать из колбэка SDK/BLE протеза.

## Мост `bridge/ws_bridge.py` (Python 3.9+, без зависимостей)

```bash
python3 bridge/ws_bridge.py --demo                 # сценарий: A, B, коактивация
python3 bridge/ws_bridge.py --demo-gestures        # перебор 7 жестов
emulator_cli | python3 bridge/ws_bridge.py --stdin # любой поток "a b" или JSON по строке
pip install -r lab/requirements.txt && python3 bridge/ws_bridge.py --lab
                                                   # сырая 4-канальная ЭМГ → фильтр 20–450 Гц → признаки
                                                   # (RMS, MAV, WL, ZC, SSC) → LDA 7 жестов → игра
python3 bridge/ws_bridge.py --demo --host 0.0.0.0  # чтобы телефон в той же Wi-Fi видел мост
```

**Безопасность моста.** ЭМГ — данные о здоровье, поэтому мост проверяет заголовок `Origin` (защита от перехвата веб-сокета чужим сайтом, OWASP WSTG). Без условий подключаются нативные клиенты (без `Origin`) и страницы с этого же компьютера (`http://127.0.0.1:*`, `http://localhost:*`). Всем остальным — standalone HTML из файла (`Origin: null`), APK, телефону в сети, GitHub Pages — нужен адрес с токеном, который мост печатает при старте: `ws://IP:8765/?token=…` (вставить целиком в Настройки → Источник → адрес). Постоянно доверенный сайт: `--allow-origin https://team.github.io`. Кадр клиента больше 4 КБ или без маски закрывает соединение; кадр источника больше 4 КБ мост пропускает (5.11: на 70 КБ мост падал); клиент, переставший читать, отключается; клиентов не больше 8. Тесты — `python -m unittest bridge/test_ws_bridge.py`.

В режиме `--lab` площадки на экране игры управляют тем, какой жест синтезирует лаборатория (игра отправляет `{"type":"intent", …}`), а распознаёт его настоящий классификатор — с реальными ошибками.

**Площадки под внешним источником (6.1, ответы организаторов 04.11, № 13).** Тач — для меню, настроек и эмуляции; с реальной ЭМГ мультитач недопустим. Поэтому при внешнем источнике площадки эмулятора появляются, только если источник их читает: лаборатория при подключении шлёт `{"type": "bridge-hello", "intents": true}` (это не кадр), и игра показывает её пульт с подписью «пульт лаборатории сырой ЭМГ». Мост с устройством или записью (`--stdin`, `--demo`), протез через хост (`Synergy.feed`, `postMessage`, Android `pushFrame`) — без площадок: «управление только сигналом». Намерение площадки доставляется один раз на изменение и на соединение: после переподключения моста удерживаемая площадка доходит снова (до 6.1 намерение, отправленное до открытия сокета, терялось). Проверка — `tests/pads.test.mjs`, `bridge/test_ws_bridge.py`, `node tests/e2e/bridge.mjs` с мостами `--demo` и `--lab`.

## Калибровка

Настройки → «Калибровка датчиков»: 3 с покоя, 3 с комфортного сжатия (≈70 %), отдых, 3 с раскрытия. Сохраняются покой и комфортный максимум каждого канала (как «чувствительность датчика» в Motorica Start), предупреждения о слабом сигнале и перекрёстных помехах. Калибровка хранится отдельно для экранного эмулятора и внешнего источника.

**Качество канала (5.27, `CALIBRATION_QUALITY`).** Шум покоя считается устойчиво: 1,4826 × медиана абсолютных отклонений покоя. Если комфортное сжатие выше покоя не больше чем на 3 таких шума, канал «плоский» и калибровка не сохраняется. Если 3 шума покоя доходят до уровня выключения канала, игра предупреждает о ложных срабатываниях, но калибровку сохраняет. До 5.27 «плоским» считался канал, где сжатие ниже 1,33 × покоя. Так отказывал любой источник со смещением (покой 1,00 В, сжатие 1,20 В) и проходил канал, где сжатие едва отличалось от шума.

**Подстройка покоя** (ко-адаптивная калибровка, `RestTracker` в `src/core/calibration.js`, параметры `CALIBRATION_ADAPT` в `src/config.js`): во время упражнения с внешним источником уровень покоя медленно следует за дрейфом сигнала — только в подтверждённом покое и не дальше 20 % диапазона. Итог сессии сохраняется в `calibrations.bridge` (поле `adaptedAt`). Большой дрейф или канал, «залипший» во включённом состоянии, — повод перекалибровать: игра скажет об этом в итогах. «Проверка навыка» идёт без подстройки, чтобы результаты недели были сравнимы.

## Электробезопасность самодельных датчиков (5.27)

Электроды на коже — это контакт с телом человека. У платы любителя нет развязки от сети, поэтому питание — только батарея: беспроводной датчик работает от своей батареи, а датчик на проводе к компьютеру или телефону — только пока это устройство отключено от зарядного устройства. Для медицинских изделий ток утечки через электроды ограничивает IEC 60601-1, а у самодельной платы такой проверки нет. Протез и сертифицированные датчики подключаются по инструкции производителя. Это же предупреждение игра показывает в «Настройки → Источник сигнала → Внешний» (`ELECTRICAL_SAFETY` в `src/core/wellbeing.js`).

## Bluetooth-датчики (v5)

Настройки → Источник «Внешний» → «Bluetooth-датчик (BLE UART)». Сервис Nordic UART `6e400001-…`, уведомления TX `6e400003-…`, строки `"a b\n"` / `"a,b\n"` / JSON — тот же `parseExternal()`. Куски по 20 байт склеиваются (`LineAssembler`), мусор без перевода строки > 512 символов отбрасывается, при обрыве — 3 попытки переподключения. После подключения обязательна калибровка (сырые единицы АЦП 0..4095). Прошивка-пример: `bridge/firmware/esp32_emg_ble/` (ESP32 + 2 × MyoWare 2.0, 50 Гц; **не компилировалась командой**). Web Bluetooth: Chrome/Edge на Android и ПК; не в iOS Safari и не в Android WebView — там `pushFrame()`.

## Нативный мост Android (v5)

`window.SynergyNative.speak(text, interrupt)`, `.stop()`, `.share(name, mime, text)` (системное «Поделиться» вместо скачивания — WebView не умеет blob-загрузки), `.print(title, html)` (PrintManager → «Сохранить как PDF»). Доступен только страницам из `android_asset` (внешняя навигация заблокирована).
