Игру ведёт тот же закон, что у протеза. Два канала ЭМГ: сгибатели закрывают кисть, разгибатели раскрывают. Распознавание — классы, отказ при низкой уверенности, набор скорости после решения. Занятие короткое и без давления. Боль, кожа и усталость останавливают план. Сессия приводит продукт к опубликованному ТЗ и не ломает то, что уже проверено.

## Задачи по приоритету

### P0. Поток 2 — СПППР (самый большой разрыв)

1. **Словарь ТЗ.** В `src/core/vocabulary.js` — набор `tz`: 0 Neutral (id `rest`), 1 Flexion, 2 Extension, 3 Pronation, 4 Supination, 5 Adduction, 6 Abduction; порядок классов = номера ТЗ; у каждого класса — ключ провода (`wire`) и ось джойстика (`axis`). Сгибание — канал сгибателей (закрытие кисти), разгибание — канал разгибателей (раскрытие); остальные четыре двигают запястье, кисть стоит. Набор `tz` — по умолчанию (`src/core/gesture-set.js`). Строка `Набор жестов организатора: …` в `MEMORY.md`, списки `GESTURES` в `lab/lab7.py` и `bridge/ws_bridge.py` — те же id в том же порядке (ворота сверяют).
2. **Жёсткий контракт.** `src/core/spppr.js`: разбор пакета `{"timestamp_ms": int, "dist": {7 ключей}}` — без молчаливых исправлений: нет ключа, лишний класс, NaN, отрицательное, сумма вне 1 ± 0,02 — пакет отклонён с кодом причины и учтён в статистике.
3. **Часы МК.** `timestamp_ms` — таймер микроконтроллера, с часами телефона не синхронизирован. Скорость и сглаживание считаются **только** по разнице `timestamp_ms` соседних пакетов. Повтор и пакет из прошлого отбрасываются; скачок назад > 1 с — перезагрузка МК (оценки сбрасываются). Смещение часов (для рисования между пакетами) — нижняя огибающая «приход − timestamp».
4. **Softmax → джойстик.** Вероятности сглаживаются экспонентой с постоянной времени по dt МК. Оси: x = flexion − extension, y = pronation − supination, z = abduction − adduction; мёртвая зона и нормировка. Команда — направление доминирующей оси (с гистерезисом входа и выхода и выдержкой по времени МК), сила — её величина. Совместная активация сгибателей и разгибателей гасит x — это и есть урок изоляции; её индекс показывается.
5. **Джиттер и интерполяция.** Пакеты через 10–100+ мс: между пакетами положение экстраполируется по скорости из dt МК (без «дёрганья»), горизонт ограничен.
6. **Потеря пакетов.** Нет пакета > 200 мс — скорость гаснет по экспоненте (инерция), игра не замирает и не падает; дольше `linkLostMs` — «сигнал потерян», после возврата — с нейтрали.
7. **Прощение ошибок классификации.** Одиночный «чужой» пакет не меняет команду (сглаживание + гистерезис + выдержка); число прощённых выбросов — в статистике (коадаптация: человек видит уверенность и запас).
8. **Эмулятор потока.** `src/input/spppr-emulator.js`: те же JSON-строки, свои часы МК со старта, джиттер 10–100+ мс, пачки, потери и обрывы > 200 мс, одиночные и «похожие» ошибки классификации, нарастание вероятности при сокращении; зерно — для тестов. Тот же эмулятор — в игре (площадки и клавиши 0–6), в CLI `tools/spppr-emulator.mjs` (NDJSON в stdout или WebSocket) и в автопилоте тестов.
9. **Одна строка.** `src/input/spppr-driver.js`: `createSppprDriver` — единственная строка, которую меняют, чтобы вместо эмулятора читать драйвер МК (WebSocket, BLE, Web Serial, хост). Мост (`parseExternal`) узнаёт пакет ТЗ из любого транспорта и отдаёт его тому же декодеру.

### P0. Поток 1 — параметры ТЗ

10. Пороговый режим: четыре состояния — канал 1 → действие 1, канал 2 → действие 2, оба → действие 3, ничего → действие 4 (`src/core/fourstates.js`). Настраиваемые: порог (по каналу), **время удержания**, **подавление ложных срабатываний** (рефрактерный период), **мёртвая зона**.
11. Пропорциональный режим: сглаживание (есть), **ограничение скорости нарастания** выхода, игровая визуализация уровня (есть).
12. Задержка ≤ 100 мс от кадра до команды при настройках по умолчанию — тест.

### P1. Удержание и мотивация

13. **Миссии сессии**: пул ≥ 10 типов, 1–3 на сессию (новичку 1, дальше 2–3; лёгкий день — 1), проверка по итогам упражнений, награда ограничена.
14. **Доля игрового времени**: учёт времени «игра с таймингом» / «остальное»; эталонная сессия попадает в 60–80 %; доля — в отчёте специалиста.
15. **Отзыв по итогам тестирования**: SUS (10 вопросов), краткая нагрузка (NASA-TLX, 4 шкалы), свободный текст; хранится на устройстве, выгружается JSON/CSV.

### P1. Документы

16. `docs/TZ_COMPLIANCE.md` — требование → решение → файл → тест. `docs/INTEGRATION.md` — контракт СПППР и замена драйвера. `docs/TASK.md` — цитаты ТЗ. `docs/JURY_STRATEGY.md` — опубликованные критерии. `docs/AI_USAGE.md` — перечень фич, план, отчёт о верификации. `README.md`, `CHANGELOG.md`, версия 6.0.0 везде (ворота).

## Правила

- Тест сначала (падает на старом коде), потом код. Набор тестов прошлых версий закреплён на наборе «Синергии» (`tests/pin-set.mjs`); набор ТЗ проверяют свои тесты и полный автопилот всех игр.
- Никаких новых зависимостей в продукте. Параметры — `src/config.js`. Имена жестов — только из `vocabulary.js`.
- Ничего не называть «доказанным»: перенос навыка на протез, польза миссий и интерфейса — гипотезы для пилота (`LIMITS.md`).
- После правок: `npm test`, `npm run build`, `node tools/gesture-drill.mjs`, `node tools/check-submission.mjs --draft`; e2e и линтер раскладки — если менялся UI.
