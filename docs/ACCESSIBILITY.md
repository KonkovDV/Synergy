# Доступность

Ориентиры: WCAG 2.2 AA, ГОСТ Р 52872-2019, Game Accessibility Guidelines (basic + intermediate).

| Требование | Решение | Где |
|---|---|---|
| Цели ≥ 24 px (2.5.8) | все кнопки ≥ 48 px, главные 64 px | `styles/app.css` |
| Альтернатива перетаскиванию (2.5.7) | сила задаётся местом касания, без движения; клавиатура | `ui/controls.js` |
| Фокус не скрыт (2.4.11) | `scroll-padding-bottom` под плавающую навигацию, видимый `:focus-visible` | CSS |
| Контраст ≥ 4.5:1 | сплошные поверхности под текстом; режим высокого контраста (чёрный/белый/жёлтый) | Настройки → Доступность |
| Изменение размера текста (1.4.4) | 100/115/130 %, текст в `rem`, канвас до +25 % | там же |
| Анимация (2.3.3) | «Меньше движения» + `prefers-reduced-motion` | там же |
| Не только цвет (1.4.1) | буквы A/B, позиция, числа в таблицах и шкалах | везде |
| Озвучивание | подсказки, отсчёт, итоги — Web Speech / нативный TTS | `services/voice.js` |
| Слабый слух | вибро-метроном, звуки продублированы текстом; музыка «Ритма» не несёт информации, которой нет на экране (ноты и линия видны) | «Ритм» |
| Одна рука, моторика | старт и «Дальше» удержанием мышцы (0,6–2,5 с), темп игр 60–100 %, адаптивная сложность | Настройки |
| Скринридеры | `aria-live` для подсказок, `role`/`aria-label` у площадок, таблицы с `caption`/`scope` | `ui/*` |
| Когнитивная нагрузка | обучение по шагам, одна главная кнопка на экране, план дня вместо выбора | — |

| Когнитивная нагрузка в настройках (W3C COGA) | постепенное раскрытие: разделы на каждый день открыты, остальные свёрнуты (`<details>`, работает с клавиатурой и скринридером); сброс прогресса можно отменить один раз | `ui/settings.js` |
| Ориентиры и заголовки | у каждого экрана есть `h1` и `main` (на экране итогов `h1` скрыт визуально; на экране игры `h1` — название и уровень, `main` — игровое поле), сигнал и управление — именованные области (`role="region"`) | `ui/*` |
| Ориентация (1.3.4, AA) | не заблокирована ни в PWA, ни в APK: телефон в держателе коляски или на столе может стоять горизонтально; в альбомной игра слева, сигнал и площадки справа | манифесты, `styles/app.css`; ворота сдачи |
| Три вспышки (2.3.1, A) | пульсация такта «Ритма» — не чаще 1,8 раза в секунду (108 уд/мин на 8-м уровне), прозрачность 15 % на тёмном фоне — ниже порога; «Меньше движения» убирает и её | `games/rhythm.js` |
| Имя, роль, значение (4.1.2) и клавиатура (2.1.1) | группы выбора названы вопросом («Боль в культе или руке», «Размер текста»…), одна остановка Tab на группу, стрелки меняют выбор (WAI-ARIA APG «Radio Group»); подпись настройки не переключает её | `ui/widgets.js` |
| Доступная аутентификация (3.3.8, AA) | PIN родителя может подставить менеджер паролей (`autocomplete`), вставка не запрещена; один Enter — одна попытка | `ui/pin.js` |
| Слабый телефон | страж кадров: < 45 к/с дольше 3 с → без частиц и вспышек, меньше пикселей холста | `core/fps.js` |
| Размер текста до 200 % (1.4.4) и перекомпоновка (1.4.10) | Android WebView умножает текст на системный масштаб шрифта (до 200 % на Android 14+): размеры в rem, дорожки сеток сжимаются, длинные слова переносятся, площадки — container queries; таблицы прокручиваются в своей области; экран игры на самом маленьком телефоне прокручивается, а не обрезается | `styles/app.css`, `tests/e2e/layout.mjs` |
| Фокус не скрыт (2.4.11) | при Tab элемент под плавающей панелью или закреплённой шапкой прокручивается в видимую часть; `scroll-padding` сверху и снизу | `app.js` (`keepFocusVisible`) |
| Клавиатура и переключатель (2.1.1) | площадки эмулятора фокусируются: пробел/Enter = удержание (кнопочные переключатели шлют эти клавиши), `aria-keyshortcuts`; F/J/цифры — на любом экране с площадками; Esc — «Назад» | `ui/controls.js`, `app.js` |
| Цели и мелкий текст | все кнопки ≥ 44 px (переключатели-строки 48 px), текст ≥ 12 px | линтер раскладки |
| Иконки | собственные SVG линиями (`currentColor`): одинаковы на всех платформах и в контрастном режиме | `ui/widgets.js` |
| Системный контраст (5.9) | высокий контраст включается сам, если система просит больше контраста (`prefers-contrast: more`) или включены принудительные цвета Windows (`forced-colors`); в настройках так и написано. Ручной переключатель по-прежнему выключен по умолчанию — это решение по умолчанию, а не проверенный выбор пользователей | `app.js`, `ui/settings.js`, `styles/app.css` |
| Тремор, слабость (5.9) | «Площадки без удержания»: касание включает канал, второе касание выключает (Game Accessibility Guidelines, «no holding»). Пробел/Enter в этом режиме тоже переключают. По умолчанию выключено: для обычной игры удержание ближе к работе мышцы | Настройки → Доступность, `ui/controls.js` |
| Игра без зрения (5.9) | в «Полёте» подсказка за 1,6 с до кольца говорит, где оно: «Кольцо выше», «ниже», «на вашей высоте — держите»; подсказка идёт в `aria-live` и в озвучивание. Звукового «радара» нет; синтез речи в WebView может не работать — тогда остаётся только скринридер | `games/flight.js` |

**Автоматическая проверка:** `tests/e2e/v5.mjs` прогоняет axe-core 4.13 (правила WCAG 2.0–2.2 A/AA и best practices) на 18 экранах и состояниях — главная, онбординг, обучение, самочувствие (с экранным эмулятором и с датчиками), прогресс, игра (демо: вступление и ход; игрок: вступление), итоги, отдых, настройки, калибровка, уровни, PIN, высокий контраст, альбомная ориентация («Мастерская» и «Сейф» в режиме жестов); там же проверяются имена групп выбора, стрелки, PIN и раскладка в альбомной. Урок 5.7: на демо-раскладке экрана игры axe засчитал правила уровня страницы, хотя `h1` и `main` не было, — поэтому аудит идёт и на экране игрока. Допустимо **ноль** нарушений любой серьёзности; CI падает иначе. Автоматика ловит лишь часть проблем (имена, роли, контраст, структура), поэтому ручная проверка остаётся обязательной.

**Линтер раскладки** (`npm run audit:layout`, `tests/e2e/layout.mjs`): 36 состояний пути игрока × 7 экранов (320 px … планшет, портрет и альбом) × 3 размера текста (100, 130, 200 %) = 756 состояний; ищет переполнение, обрезанный и мелкий текст, наложения, цели < 44 px, элементы под панелями и скрытый фокус. С 5.9 в пути есть системный высокий контраст и принудительные цвета, а при обычном размере текста на телефонах от 360 px — слова, разорванные посередине (при 130–200 % и на 320 px перенос внутри слова допустим: он лучше текста за краем экрана). Холст игр и радар линтер не видит — их геометрия проверяется тестами (`rhythmLayout`, `radarLayout`).

Это автоматические проверки по ориентирам WCAG 2.2, а не заключение о соответствии: без ручной проверки со скринридером и без людей с инвалидностью «соответствует WCAG» не говорим.

Не проверено вручную: TalkBack/VoiceOver на реальных устройствах (PLAN.md 2.9).
