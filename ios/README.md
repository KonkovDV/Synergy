# «Синергия» для iPhone и iPad

Та же игра, что в APK и PWA: собранный `dist/` внутри приложения, офлайн, без аккаунта. Оболочка на Swift (SwiftUI + WKWebView) — одна из платформ, которые «Моторика» назвала на митапе 21.10.2026. Сдача по ТЗ — устанавливаемая сборка; для Android это `release/Synergy-6.3.3.apk`, для iPhone — этот проект, который собирается в Xcode (раздел «Сборка»).

## Как запускается и работает

```
 Иконка «Синергия»  ─┐
 synergy://play?…    ├─▶ SynergyApp (SwiftUI) ─▶ LaunchRequest: проверка ссылки ─▶ GameView (WKWebView)
 synergy://launch    ┘                                                              │
                                                    synergy-app://game/index.html?… ◀┘  BundleSchemeHandler
                                                    (файлы из папки dist внутри приложения, офлайн)
 Страница ─ window.SynergyNative ─▶ NativeBridge: голос, вибрация, тема, «Поделиться», печать
 Страница ─ synergyHost (только запуск с x-success) ─▶ NativeBridge ─▶ x-success: результат и пороги вызвавшему
```

1. **Запуск.** С иконки — главная. По ссылке `synergy://play?game=grip&level=2&gestures=tz&side=left&closeThreshold=60&openThreshold=200` — нужное упражнение, рука и пороги приложения протеза (ответы 04.11, № 15–16). По ссылке `synergy://launch` — главная: так раздел игр Motorica Start открывает игру своего каталога (`docs/embed/motorica-start-catalog.json`). Неизвестные значения отбрасываются по тем же шаблонам, что у Android (`MainActivity.launchQuery`) и у страницы (`services/host.js`); тесты сверяют их.
2. **Страница.** Игра грузится из пакета приложения под собственным адресом `synergy-app://game/` (`BundleSchemeHandler.swift`, `WKURLSchemeHandler`). Так встраивают веб-игру в iOS-приложения (Capacitor, Ionic): один постоянный origin для прогресса в `localStorage`, верные MIME-типы, CSP `'self'` означает само приложение. Выйти за пределы `dist` нельзя: другой хост, `..` или папка — «не найдено». До 6.3.2 страница открывалась как `file://`.
3. **Сигнал.** Управление — сигналом мышц: экранный эмулятор (площадки), мост по сети (`ws://адрес:8765`, `bridge/ws_bridge.py`, эмулятор организатора) или приложение протеза как хост. Пока приложение открыто, экран не гаснет (`isIdleTimerDisabled`): человек играет без касаний, а iOS через 30–60 с бездействия блокирует экран. В APK так же — `FLAG_KEEP_SCREEN_ON`.
4. **Нативные возможности** — через `window.SynergyNative`, тот же объект, что даёт APK; ветки для iOS в JS нет (`tests/v530.test.mjs` сверяет методы):

| Возможность | В Safari на iPhone | В приложении |
|---|---|---|
| Голос подсказок | зависит от системы | `AVSpeechSynthesizer`, русский голос |
| Вибрация | нет (`navigator.vibrate` в iOS не работает) | `UINotificationFeedbackGenerator`, `UIImpactFeedbackGenerator` |
| Тёмная тема по системе | да | да, и при смене темы на ходу |
| «Поделиться» отчётом и копией | скачивание | системное окно «Поделиться» |
| Печать отчёта специалисту | печать страницы | AirPrint и «Сохранить в PDF» |
| Подтверждения («Сбросить калибровку?») | да | `UIAlertController` |
| Экран не гаснет во время игры | нет | да |
| Возврат в приложение протеза с результатом | — | `x-success` (ниже) |

5. **Голос подсказок.** Подсказки, которые человек включил («Голос» в настройках), звучат так, как Apple советует навигаторам и приложениям тренировок: категория `.playback` в режиме `.voicePrompt` (`AVAudioSession`). Подсказка слышна и при беззвучном режиме; музыка человека на время подсказки приглушается, подкаст встаёт на паузу, после подсказки звук возвращается другим приложениям (`notifyOthersOnDeactivation`). До 6.3.2 первая подсказка выключала музыку человека, а при беззвучном режиме голоса не было.
6. **VoiceOver.** Страница отдаёт подсказки, отсчёт и вердикты живыми областями (`role="status"`), и VoiceOver читает их сам. Поэтому при включённом VoiceOver собственный голос игры молчит, иначе каждая подсказка звучала бы дважды и вперемешку. Вибрация «готовится» заранее (`prepare()`): отклик Taptic Engine без задержки.
7. **Прогресс.** Он хранится в хранилище WebKit приложения под постоянным адресом `synergy-app://game` и никуда не уходит. Установленное приложение просит не вытеснять его при нехватке места (`navigator.storage.persist()`, 6.3.2). Копия в файл — «Настройки → Данные → Сохранить копию» (системное «Поделиться»: «Файлы», почта).
8. **Площадки эмулятора.** Удержание площадки — это и есть «сокращение мышцы». В iOS долгое нажатие на картинку открывает системное меню «Скопировать · Сохранить»; с 6.3.2 его нет ни в Safari, ни в PWA, ни в приложении (`-webkit-touch-callout: none` в `styles/app.css`, `allowsLinkPreview = false`).

## Интеграция с приложением протеза: роутинг

По ответам организаторов (04.11, № 15–16) и экспертов (07.11, № 16) интеграция — это запуск и обмен данными, а не игра внутри чужого приложения. На iOS это делается ссылками между приложениями:

- **Туда.** Приложение протеза открывает `synergy://play?…` (или `synergy://launch`) через `UIApplication.shared.open`. Чтобы проверить, установлена ли игра (`canOpenURL`), ему нужно указать `synergy` в `LSApplicationQueriesSchemes` своего Info.plist.
- **Обратно (x-callback-url, 6.3.2).** Если в ссылке есть `x-success=<ссылка вызвавшего приложения>`, то, когда человек заканчивает («Вернуться в приложение» на итогах), игра открывает эту ссылку и дописывает к ней:
  - `synergy=close`, `reason` — `done` или `back`;
  - `result` — JSON последнего `synergy:result`: игра, уровень, очки, звёзды, навыки, `channels` — пороги упражнения 0–255;
  - `settings` — JSON последнего `synergy:settings`: рука, ползунки, пороги.

  Это те же сообщения протокола 1, что получает встраивающий хост (`docs/embed/README.md`). Имени и ответов о самочувствии в них нет.

  Пример:

  ```text
  synergy://play?game=grip&level=2&side=left&x-success=motorica%3A%2F%2Fsynergy
  → motorica://synergy?synergy=close&reason=done&result=%7B…%7D&settings=%7B…%7D
  ```

  Принимается только собственная схема вызвавшего приложения: `http`, `https`, `file`, `javascript`, `data`, `mailto`, `tel`, `sms`, `facetime` и схемы самой игры отклоняются. Длина ссылки — не больше 512 символов.
- **Сигнал.** Отдельному приложению Motorica Start поток ЭМГ так не передаст: снимок в общей группе приложений читает только приложение с подписью «Моторики» (`docs/RESEARCH.md` §19). Пути сигнала на iPhone — ниже. Ключи `side`, `closeThreshold`, `openThreshold` и сам возврат по x-success — наше предложение: имён в Motorica Start нет. Это вопрос 12 чек-пойнта 09.11 (`submission/CHECKPOINT-2.md`).
- **Безопасность ссылок.** Своя схема (`synergy://`) — то, чем пользуется каталог игр Motorica Start (`<urlScheme>://launch`). Universal Links надёжнее (схему может объявить и чужое приложение), но им нужен свой домен с `apple-app-site-association`; у прототипа его нет. Поэтому в ссылке запуска нет секретов, а в ответе по `x-success` нет имени и самочувствия: только игровые числа и пороги.
- **Запасной путь — WebView внутри приложения протеза:** `docs/embed/ios/SynergyHostView.swift`. Там хост сам подаёт сигнал (`pushFrame`) и слушает `synergyHost` с первой секунды. Своё приложение, которое встраивает игру, лучше тоже грузить через обработчик схемы — как `ios/Synergy/BundleSchemeHandler.swift`.

## Датчики на iPhone

В iOS нет Web Bluetooth, поэтому есть три пути:
- сигнал с компьютера по сети: мост `bridge/ws_bridge.py` или эмулятор организатора, `ws://адрес:8765` в «Источник сигнала» (разрешение «Локальная сеть» iOS спросит один раз);
- приложение протеза как хост (WebView): кадры через `postMessage` (`docs/embed/README.md`);
- экранный эмулятор — без датчиков.

## Сборка

Нужны Mac с Xcode 16 или новее, Node 18+ и [XcodeGen](https://github.com/yonaskolb/XcodeGen) 2.44+.

```bash
npm ci && npm run build
```

```bash
xcodegen generate --spec ios/project.yml
```

```bash
open ios/Synergy.xcodeproj
```

Затем в Xcode: Signing & Capabilities → ваша команда Apple ID → Run. Первая команда собирает `dist/` — игру, которую приложение кладёт в себя; вторая создаёт `ios/Synergy.xcodeproj` (в git он не хранится).

Без Mac есть два пути:
- workflow `.github/workflows/ios.yml` (запуск вручную или по тегу `v*`) собирает приложение для симулятора без подписи, запускает его, открывает ссылку на «Две руки» и сохраняет снимки экрана;
- `sh tools/check-ios.sh` с Swift для Linux — проверка типов по заглушкам SDK и тесты логики (раздел «Как проверено»).

## На телефон и в TestFlight

1. В Xcode у цели Synergy задать свою команду (`DEVELOPMENT_TEAM`) и, если нужно, свой `PRODUCT_BUNDLE_IDENTIFIER`.
2. Подключить iPhone, выбрать его и нажать Run. С бесплатным Apple ID сборка работает 7 дней; на телефоне нужно включить режим разработчика (iOS 16+: Настройки → Конфиденциальность и безопасность → Режим разработчика).
3. TestFlight: Product → Archive → Distribute App → App Store Connect. Нужен платный аккаунт разработчика. Внутренние тестировщики команды получают сборку сразу; внешним по публичной ссылке нужна проверка бета-версии Apple — до загрузки 11.11 на неё не стоит рассчитывать. App Store Connect принимает только сборки свежего Xcode: какой нужен сейчас, Apple пишет в App Store Connect.
4. Манифест конфиденциальности (`Synergy/PrivacyInfo.xcprivacy`, 6.3.2) App Store Connect проверяет с 2024 года: игра не отслеживает, ничего не собирает с устройства и не вызывает API из списка «с объяснением причины».
5. Для App Store, если до него дойдёт: категория — образовательные игры (`LSApplicationCategoryType`); ответы анкеты о возрасте и «медицинской информации» — по `docs/LEGAL.md`. Правило проверки 1.4.1 строже к приложениям, которые могут влиять на лечение. «Синергия» говорит на первом же экране, что это тренажёр, а не медицинское изделие, и программу занятий человек согласует со специалистом (`src/core/wellbeing.js`, `SAFETY_RULES`).

## Без установки: PWA

Safari → «Поделиться» → «На экран „Домой“». Игра открывается без адресной строки и работает без сети (service worker). Нет вибрации, системного «Поделиться», экрана без блокировки и возврата в приложение протеза — для них нужно приложение.

## Как проверено

Mac на стенде нет, поэтому Xcode здесь не запускался и на iPhone приложение не ставилось. Проверено:
- **Проверка типов Swift по заглушкам SDK** (`sh tools/check-ios.sh`, 6.3.2): Swift 6.2.1 для Linux проверяет все файлы `ios/Synergy/` и пример хоста `docs/embed/ios/SynergyHostView.swift` по заглушкам UIKit, WebKit, SwiftUI и AVFoundation (`ios/stubs/`). Заглушки повторяют сигнатуры Apple. Методы делегатов, которые приложение реализует, в них обязательные — опечатку в имени ловит компилятор. Это проверено: три подложенные опечатки (`didFinish`, `isIdleTimerDisabled`, `start` у обработчика схемы) проверку не прошли. Заглушки — не SDK: то, чего в них нет, проверяет только Xcode.
- **Тесты логики на Swift** (`tests/ios/main.swift`, 42 проверки), запуск тем же скриптом: ссылки запуска, отказ в чужих и опасных `x-success`, ответ вызвавшему приложению (JSON возвращается без потерь), файлы `synergy-app://game/` (выйти за `dist` нельзя, в том числе через `%2e%2e`).
- **Тесты на JS** (`npm test`): методы `SynergyNative` у iOS и Android совпадают; правила ссылок совпадают с Android и страницей; регистрация `synergyHost` — только для запуска с `x-success` и только после загрузки страницы; манифест конфиденциальности подключён; версия в `project.yml` равна версии игры (ворота сдачи). С заданным `SWIFTC` `npm test` запускает и `tools/check-ios.sh`.
- **В CI на GitHub** — задание `ios-check` (официальный образ Swift, закреплён по хешу) и `ios.yml` на macOS, когда его запускают вручную.

## Что ещё не сделано (план — `docs/dev/PLAN.md`)

- Сборка в Xcode и прогон на iPhone, VoiceOver.
- Копия прогресса в хранилище приложения. Сейчас прогресс живёт в хранилище WebKit приложения; копия в файл — «Настройки → Данные → Сохранить копию».
- Размер текста по системной настройке iOS (Dynamic Type). Сейчас текст увеличивается настройкой игры «Размер текста».
- Цвет значков строки состояния при теме игры, отличной от системной. По умолчанию тема игры следует системе, и всё читается; если в игре выбрать тёмную тему при светлой системной, часы и батарея над страницей могут слиться с фоном.
- Датчики Bluetooth напрямую через Core Bluetooth (опорная прошивка `bridge/firmware/esp32_emg_ble`), без компьютера и моста.
