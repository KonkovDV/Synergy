# План сотрудничества MOTUS Lab и ГК «Моторика»

Презентация о дальнейшей совместной работе — не питч. 65 слайдов в девяти разделах. Основа — реестр рисков «Моторики» из её годового отчёта 2025: меры по 13 из 30 ключевых рисков есть в наших пакетах, в том числе по О6 «Кадровый голод» и РЕГ1 «Изменения в законодательстве» из самой опасной клетки карты. Дальше — правила рынка, кто наступает на пятку (Steplife, «Максбионик» и ГК «Метиз», госкорпорации, новые игроки), сравнение по двенадцати направлениям — где «Моторика» впереди и где отстаёт, три ответа на три давления конкуренции из годового отчёта, голос пользователей по всем отзывам RuStore, взгляд восьми кресел руководства, боли компании с цепочкой «решение → доказательство → процесс → эффект», этапы пациентского пути, вклад в инвестиционную историю к IPO, бизнес-эффект по семи рычагам, команда и медицинское ПО с врачом в цикле, 11 пакетов работ в четырёх треках, пилот на 8 недель, данные, право, границы утверждений и решения на встрече.

## Как устроено

Один источник — модули в `tools/motorica/`:

- `data.mjs` — факты о «Моторике» и конкурентах с источниками, кресла, слабые места, пакеты работ, стыки, роли, риски, решения;
- `model.mjs` — модель эффекта: база 2025 года, сценарии, рычаги L1–L7;
- `slides.mjs` — слайды: раздел, маршрут, заголовок, данные, речь, источники; ссылки между слайдами — `{#layout}` и `{#wp:WP5}`;
- `render.mjs` — HTML и SVG каждого макета, без атрибутов `style` (строгая CSP).

Из них `tools/motorica-site.mjs` собирает `index.html`, `plan.html` (из `PLAN.md`) и `sw.js`, а `tools/motorica-deck.cjs` открывает ту же страницу в Chromium (`?print=1`) и печатает PDF, снимает слайды для PowerPoint и `og.jpg` и пишет `slides.json`. Поэтому сайт, PDF и PPTX не расходятся. Калькулятор сайта (`app.js`) и Excel-книга (`tools/motorica-model.py`) считают по тем же формулам, что `model.mjs`; проверки сверяют все три.

## Как пересобрать

```bash
npm i --no-save pptxgenjs@3.12.0 sharp@0.34.4 react-icons@5.5.0 react@18.3.1 react-dom@18.3.1 qrcode@1.5.4
```

```bash
node tools/motorica-site.mjs && node tools/motorica-deck.cjs && node tools/motorica-site.mjs
```

```bash
python3 tools/motorica-model.py && python3 tools/motorica-model.py --check
```

```bash
npm run check:motorica && npm run check:motorica-page
```

Второй запуск `motorica-site.mjs` нужен, чтобы ссылки на свежие PDF и PPTX получили новые `?v=` и размеры. Для `--check` нужен LibreOffice: он пересчитывает книгу и сверяет итоги с `slides.json`.

### Колода в Figma — слоями

```bash
node tools/motorica-figma.cjs
```

Скрипт кладёт в `dist/figma/` четыре самодостаточных HTML-снимка колоды: слайды 1–20, 21–40, 41–60 и 61–65. В каждом снимке шрифты и картинки встроены, иконки развёрнуты, а стили SVG перенесены в атрибуты. Каждый файл импортируется в Figma одним вызовом `html_to_figma` (Figma MCP) с `cssSelector: "#deck > .s"`: файл отправляется POST на выданный адрес с `Content-Type: text/html`. Каждый слайд станет фреймом 1600 × 900 из редактируемых слоёв с именем «NN · заголовок», фреймы лягут сеткой в 5 колонок. На тарифе Starter у Figma MCP 20 вызовов чтения в месяц, импорт колоды тратит четыре из них. Почему снимок устроен именно так, сказано в шапке скрипта.

## Правила

- Числа «Моторики» — только из открытых источников: годовые отчёты за 2024 и 2025 годы, IR-брошюра 2025, результаты I полугодия 2026 года, пресса, открытый код. У каждого слайда — строка источников; цитаты — дословно, со страницей. Чего нет в первоисточнике, того нет в колоде: фактчекинг 20.11.2026 убрал неподтверждённые цифры и цитаты.
- Иллюстрации с девушкой — образ амбассадора, а не реальный пользователь; это написано в строке источников каждого такого слайда. Протез на них обезличен: без изделий и логотипа «Моторики».
- Дизайн-слой 2026 (в конце `site.css`): фон раздела — свой арт (Figma, ChatGPT Image 2.5), свечение, сетка точек и зерно; карточки — матовое стекло с бликом по кромке; акценты заголовков и крупные цифры — градиент; столбцы и полосы графиков — градиенты из спрайта (`#g-mint` и другие); иконки кресел — 3D-стекло. В колоде блоки слайда появляются по очереди (без этого — при «уменьшить движение»). В печати (из неё PDF) акценты сплошным цветом, без размытых теней и зерна, а картинки — JPEG-двойники: PDF не знает WebP, и Chrome встроил бы картинку без сжатия.
- На телефоне (лента уже 900 px) широкие схемы — карта компетенций, связи портфеля, шаги WP1, дорожная карта, недели, дерево эффекта, карта рисков, правило решения — не сжимаются до нечитаемого, а листаются вбок в своём блоке (`.hscroll`, его добавляет `app.js`); шаги WP1 там же идут нумерованным списком.
- Вёрстку каждого слайда проверяет `tools/motorica-layout.mjs` (шаг 5г `check:motorica-page`: печать, колода и лента 390 px): нет обрезанных блоков, текста на тексте и на картинках, подписей за краем и вне своих плашек, слипшихся подписей, линий сквозь буквы, фрагментов не того размера или цвета.
- Слайд «Границы утверждений» говорит, чего мы не утверждаем: тренажёр — не медизделие, модель — не прогноз, перенос навыка на протез не доказан, закрытый код «Моторики» мы не видели.
- Модель — иллюстрация масштаба, а не прогноз выручки компании: база 2025 года заморожена, рост рынка, ноги, центры, нейротех и экспорт не учтены. Допущения помечены и проверяются пилотом и данными «Моторики».
- Публичный репозиторий и сайт — без переговорных позиций и цен: смета — после рабочей сессии этапа 0.
- Контакты — только на слайде «Решения» в одном блоке страницы между `contacts:begin` и `contacts:end`; `check:motorica` не пропустит их в другом месте, в том числе в `slides.json`.
- Страница не индексируется (`noindex`), без внешних запросов (CSP `default-src 'self'`), без скрипта показывает слайды лентой, работает офлайн.
- `check:motorica` — слайды на странице = страницы PDF = слайды PPTX = `slides.json`, тот же текст, `?v=`, CSP, alt, якоря, маршруты, план = модель. `check:motorica-page` — колода в Chromium: клавиши, `#sN`, маршруты, заметки, калькулятор = модель, ссылка на расчёт, правило решения, тренажёр, интерактив не двигает вёрстку, 320–2560 px, axe-core — 0 нарушений, офлайн.
