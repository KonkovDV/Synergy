## Чего в репозитории нет и не должно появиться

- Ключей подписи и паролей выпуска. Отладочный ключ собирается в `tools/.cache` и в git не входит (`.gitignore`). Пароль этого ключа записан в `tools/build-apk.sh` и секретом не является: самого ключа в репозитории нет.
- Учётных данных чужих проектов. В «Синергию» они не переносились и здесь не повторяются.
- Бинарников выпуска. `release/*.apk` и `release/*.html` собирает `tools/build-apk.sh`, в архив кладёт `tools/pack.sh`. Ворота не пропустят их в git.
- Фамилий, пока команда сама не впишет их в `AUTHORS.md`.
- Результатов сессий с людьми, пока сессий не было.

## Выгрузка на GitHub

Делает капитан, когда есть адрес. Порядок уже записан в `PLAN.md` 0.1 и B.1. Коротко:

1. Приватный репозиторий. `git remote add origin …` и `git push -u origin main`. Историю не переписывать.
2. Включить private vulnerability reporting, secret scanning, Dependabot, CodeQL. Как сообщить об уязвимости — `SECURITY.md`.
3. Pages → Source: GitHub Actions, если нужна страница и репозиторий публичный: сайт Pages открыт всем даже у приватного репозитория, поэтому `pages.yml` у приватного публикацию пропускает. Сайты одного владельца на `github.io` делят хранилище браузера; для занятий людей нужен свой домен (`docs/LEGAL.md` §3).
4. Секреты подписи APK — только в секретах репозитория (`KEYSTORE_BASE64`, `KEYSTORE_PASS`, `KEY_ALIAS`), не в файлах.
5. Значок CI в README — только после первого зелёного прогона, с абсолютным адресом. Пока прогона не было, значка нет (`LIMITS.md`).
6. Тег сдачи `submission-ДАТА` — на последний коммит до дедлайна, не раньше ответа организатора по пункту 0.6.
