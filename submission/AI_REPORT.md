# «Синергия» — отчёт об использовании ИИ

Игра-тренажёр управления бионическим протезом кисти по ЭМГ, версия 6.3.3. Задание геймджема «Моторика: Код движения» разрешает ИИ-инструменты при условии, что команда даёт перечень реализованных с их помощью функций, план и отчёт о верификации. Этот отчёт отвечает на это по пунктам; подробный журнал по версиям — `docs/AI_USAGE.md`, числа прогонов этой сборки — `docs/evidence.json`.

Автор результата — человек: команда ставила задачи, принимала решения, проверяла и принимала результат (ГК РФ ст. 1228). По правилу команды в документах проекта нет названий конкретных моделей и сервисов.

## 1. Какие ИИ-инструменты использовались и как

| Инструмент | Для чего | Как работал |
|---|---|---|
| Ассистент программирования на большой языковой модели, агентный режим | код игры, тесты, инструменты сборки и проверки, документы | в изолированной облачной среде: читал репозиторий, запускал тесты, сборку и браузерные проверки, вносил правки; каждый заход заканчивался коммитом с журналом в `CHANGELOG.md` и `MEMORY.md` |
| Генератор изображений по текстовому описанию | иллюстрации: Жар-птица, тренер Мио, кисти жестов, комнаты и предметы игр, значки | промпты и эталоны стиля — команда (`docs/REGEN.md`, `docs/GAME_VISUALS.md`); отбор кандидатов, вырезка фона и подключение — по описанию в `docs/ART.md` |
| Поиск и сводка источников | обзор литературы по тренажёрам ЭМГ и практике протезирования | ссылки и выводы — `docs/RESEARCH.md`; клинические утверждения сверены с первоисточниками |

Звук и музыка генерируются кодом, чужих ассетов нет. Ни одна функция игры не обращается к ИИ во время работы: игра работает офлайн, без сети и без моделей.

## 3. План работы и проверки

Каждое изменение шло одним циклом (`PLAN.md`, раздел A): **тест → код → все тесты → сборка → браузерные проверки → документы → коммит**. Правила: числа в документах только из прогонов (их сверяют ворота сдачи), каждая новая проверка ворот получает случай с подложенной ошибкой, две неудачи подряд — остановка и запись в журнал решений.

| Что проверяется | Как | Критерий приёмки |
|---|---|---|
| Логика ядра, игр, правил; документы совпадают с кодом | `npm test` | 0 упавших тестов |
| Поток СПППР по ТЗ на всех уровнях игр | `npm run test:tz` | все уровни четырёх игр в трёх схемах — не меньше 2★ на среднем потоке, не меньше 1★ на плохом |
| Доступность интерфейса | `npm run e2e:a11y` (axe-core, WCAG 2.2 A/AA) | 0 нарушений, 0 ошибок JavaScript |
| Раскладка на телефонах, планшете и ноутбуке | `npm run audit:layout` | 0 находок |
| Встраивание в приложение другого происхождения | `npm run e2e:embed` | все проверки пройдены |
| Готовность к сдаче | `node tools/check-submission.mjs` | 0 ошибок |
| Телефоны, скринридер, живые игроки, тексты о здоровье | вручную, командой | без падений; совет всегда ведёт к специалисту |

## 4. Критичные модули: план и результаты проверки

Критичные — модули, ошибка в которых учит человека неправильному управлению или ломает прохождение.

| Модуль | Риск | Как проверено | Результат на 6.3.3 |
|---|---|---|---|
| Ядро сигнала двух каналов (`src/core/signal.js`) | ложное срабатывание, задержка больше 100 мс из ТЗ | тесты задержки на 30 и 60 Гц, тесты порога, удержания, подавления ложных срабатываний; фаззинг 329 тысяч шагов (6.3.1) | команда — следующим кадром: 33 мс при 30 Гц, 17 мс при 60 Гц; нарушений инвариантов нет |
| Модель кисти (`src/core/hand.js`) | поведение не как у протеза | тесты по ответам экспертов 09.11: постоянная скорость, рост силы при удержании, раскрытие сразу открывает | совпадает с ответами 1а–1д |
| Декодер СПППР (`src/core/spppr.js`) | дёрганье при джиттере, зависание при потерях, ошибочная команда | жёсткий контракт пакета, часы МК, джиттер 10–100+ мс, потери больше 200 мс, одиночные ошибки, округлённые вероятности, любая пара «2 жестов» | все уровни на 10 и 50 Гц на обоих словарях и на паре пронация/супинация (`npm run test:tz`) |
| Баланс уровней | непроходимый уровень | автопилот и модель новичка проходят каждый уровень каждой игры в каждой схеме | все уровни проходимы |
| Интерфейс | недоступный экран, наложения | axe — 39 светлых и 10 тёмных состояний; линтер раскладки — `docs/evidence.json` | 0 нарушений, 0 находок |
| Ворота сдачи (`tools/check-submission.mjs`) | проверка молча не работает | каждая проверка — случай с подложенной ошибкой на копии репозитория | каждая подложенная ошибка ловится |

Весь набор — 621 тест, итог прогона этой сборки — таблица «Главное» в `README.md`.

## 5. Ошибки ИИ, найденные проверкой, и как они исправлены

- **Один хват у кисти по умолчанию (6.0–6.3.1).** Когда набор жестов ТЗ стал набором по умолчанию, у кисти двух каналов остался один хват с именем «Сгибание», а картинка не сжималась в кулак. Тесты были закреплены на другом наборе жестов и этого не видели. Нашёл аудит по снимкам каждого экрана; исправлено в 6.3.2, тесты теперь закреплены и на наборе по умолчанию.
- **Недельная проверка навыка (до 6.3.1).** Документы называли интервал Агрести — Каффо, а код сравнивал с его погрешностью сырую разницу долей: при неизменном навыке игра в 14,6 % случаев говорила «навык вырос» вместо допустимых 5 %. Найдено полным перебором исходов, исправлено, закреплено тестом.
- **Округлённые вероятности СПППР (до 6.3.1).** Строгая проверка суммы отбрасывала пакеты устройства, которое округляет вероятности: 2,3 % пакетов при двух знаках, 66 % при одном. Допуск теперь равен тому, что может дать округление.
- **Удар «Ритма» на 10 Гц (до 6.2).** Удар судился по времени прихода пакета, и на 10 Гц смещался на 86 мс против 52 мс на 50 Гц. Теперь — по часам микроконтроллера: одинаково на 10, 30 и 50 Гц.
- **Пара «2 жестов» (6.3.3, до выпуска).** Новые тесты поймали два промаха первой версии: ключи словаря шли в порядке пары, а не ТЗ, и эмулятор устройства другой пары выдавал сгибание, которого такое устройство не знает. Исправлено до сборки.
- **Устаревшие тексты.** После ответов экспертов документы ещё говорили «B ослабляет хват» и «выдержка 50 мс». Ворота сдачи и вычитка нашли их, 6.3.3 исправила.

## 6. Что проверено людьми, границы и ответственность

- **Проверено автоматически на этой сборке:** тесты, поток СПППР на всех уровнях, доступность, раскладка, встраивание, ворота сдачи, сборка APK со сверкой Java-кода с API 29.
- **Сделано командой:** постановка и приёмка механик, плейтест на эмуляторах, правка текстов, сверка игры с ответами экспертов «Моторики» от 04.11, 07.11 и 09.11.
- **Вынесено в пилот:** игра с реальным протезом и реальным потоком СПППР (по ТЗ на геймджеме — только эмуляторы), плейтест с пользователями протезов, установка APK на парк телефонов, TalkBack, вычитка текстов о здоровье специалистом, сборка приложения iPhone в Xcode. Протокол пилота готов — `docs/USABILITY_PROTOCOL.md`, полный реестр — `LIMITS.md`.
- **Границы.** Игра — тренажёр, а не медицинское изделие: клинический эффект и перенос навыка на протез измеряются в пилоте. Игра рассчитана на сигнал протеза; экранный эмулятор служит для демонстрации и отладки.
- **Ответственность.** Решения о механиках, словах о здоровье и границах продукта принимала команда; каждое утверждение документов либо подтверждено прогоном, либо помечено как гипотеза.
